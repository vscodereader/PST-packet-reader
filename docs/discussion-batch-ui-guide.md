# CSV 기반 네이버 증권 토론 batch UI 사용 가이드

이 문서는 새로 추가한 `패킷 기반 종목/글/댓글 실행 설정` 화면의 사용 방법과 내부 동작을 설명한다.

## 목적

PowerShell에서 매번 제목과 내용을 입력하지 않고, CSV 파일에 작성한 제목, 내용, 댓글내용을 가져와서 네이버 증권 토론방 글쓰기 또는 댓글쓰기를 실행한다.

실제 등록 요청은 프론트 화면이 직접 보내지 않는다. 화면은 설정을 입력받고, Tauri command를 통해 Rust 함수가 기존 패킷 기반 등록 함수를 호출한다.

## CSV 파일 형식

CSV 첫 행은 반드시 아래처럼 작성한다.

```csv
제목,내용,댓글내용
```

실제 사용할 데이터는 2행부터 작성한다.

```csv
제목,내용,댓글내용
첫 번째 제목,첫 번째 본문,첫 번째 댓글
두 번째 제목,두 번째 본문,두 번째 댓글
세 번째 제목,세 번째 본문,세 번째 댓글
```

가져오기 결과는 다음처럼 적용된다.

- 2행 1열부터 마지막 행 1열까지: 제목 목록
- 2행 2열부터 마지막 행 2열까지: 내용 목록
- 2행 3열부터 마지막 행 3열까지: 댓글내용 목록

빈 값은 제외한다. 첫 행의 `제목`, `내용`, `댓글내용` 헤더는 텍스트창에 들어가지 않는다.

Excel을 사용하는 경우 `.xlsx` 그대로 가져오지 말고, `CSV UTF-8` 형식으로 저장한 뒤 가져온다.

## 화면 입력 순서

1. `가져오기` 버튼을 누른다.
2. CSV 파일을 선택한다.
3. `종목` 입력창에 종목명 또는 6자리 종목코드를 입력한다.
4. 검색 결과에서 원하는 종목을 클릭한다.
5. 종목을 직접 검색하지 않고 고르고 싶으면 종목 입력창 오른쪽 `↓` 버튼을 누른다.
6. 목록에서 원하는 종목을 클릭한다.
7. 선택된 종목 chip을 확인한다.
8. 글쓰기 또는 댓글쓰기 체크박스를 선택한다.
9. 제목, 내용, 댓글 내용 텍스트창을 확인하고 필요하면 직접 수정한다.
10. 제목, 내용, 댓글 내용 각각의 선택 방식을 고른다.
11. 작성 개수를 `3개` 또는 `5개` 중 하나로 고른다.
12. `설정 저장`을 누른다.
13. `실행`을 누른다.

## 종목 선택

종목 검색은 Rust command `search_stocks`가 네이버 증권 API를 호출해서 가져온다.

가져오는 값은 다음 세 가지다.

- 종목명
- 6자리 종목코드
- 토론방 링크

선택한 종목은 chip 형태로 표시된다. chip에는 `종목명 · 종목코드`가 보인다. 같은 종목은 중복 추가하지 않는다.

선택된 종목 상세 영역에는 아래 형식으로 표시된다.

```text
종목명 / 종목코드 / 링크
```

## 글쓰기와 댓글쓰기 선택

화면에는 두 개의 체크박스가 있다.

- 글쓰기
- 댓글쓰기

글쓰기만 체크하면 글쓰기만 실행한다.

댓글쓰기만 체크하면 댓글쓰기만 실행한다.

둘 다 체크하면 각 회차마다 글쓰기와 댓글쓰기를 모두 실행한다.

아무것도 체크하지 않으면 저장이나 실행 시 `행동을 선택하세요.` 오류가 나오고, 체크박스 영역에 빨간 테두리가 생긴다.

## 제목, 내용, 댓글내용 선택 방식

각 텍스트창 아래에는 세 가지 선택 방식이 있다.

- 랜덤
- 순차
- 1개만

### 랜덤

목록 중 하나를 실행 시점에 고른다.

예를 들어 제목이 5개 있으면 5개 중 하나를 선택한다.

### 순차

첫 번째 실행에는 첫 번째 값을 사용하고, 두 번째 실행에는 두 번째 값을 사용한다.

값보다 실행 횟수가 많으면 다시 처음부터 반복한다.

예를 들어 제목이 2개이고 실행 개수가 5개이면 아래처럼 사용한다.

```text
1회차: 제목 1
2회차: 제목 2
3회차: 제목 1
4회차: 제목 2
5회차: 제목 1
```

### 1개만

값이 정확히 하나일 때만 선택할 수 있다.

값이 여러 개면 `1개만`은 비활성화된다.

## 텍스트창 수정

CSV에서 가져온 뒤에도 제목, 내용, 댓글내용 텍스트창에서 직접 수정할 수 있다.

수정 후 `설정 저장`을 누르면 텍스트창에 남아 있는 값이 최종 실행 값이 된다.

여러 값을 구분할 때는 화면에서 `---` 줄을 사용한다.

```text
첫 번째 제목
---
두 번째 제목
---
세 번째 제목
```

## 작성 개수

작성 개수는 `3개` 또는 `5개` 중 하나만 선택한다.

각 등록이 끝난 뒤 다음 등록 전까지 1분을 기다린다.

여기서 등록이란 아래까지 포함한다.

- 글쓰기: 글 등록 요청 완료 후 새로고침
- 댓글쓰기: 댓글 등록 요청 완료 후 새로고침

## 대기 타이머

한 건의 등록이 완료되고 1분 대기가 시작되는 순간, 화면에 카운트다운 타이머가 표시된다.

타이머는 `설정 저장` / `실행` 버튼 바로 아래에 위치한다.

```
설정 저장    실행

다음 실행 대기 중
    00:58

실행 완료: ...
```

타이머 동작 규칙은 다음과 같다.

- 앱을 열거나 CSV를 가져오거나 옵션을 선택하는 것만으로는 타이머가 시작되지 않는다.
- 글쓰기 또는 댓글쓰기가 실제로 완료되고 페이지 새로고침까지 끝난 뒤에만 타이머가 시작된다.
- 타이머는 60초부터 00:00까지 1초씩 줄어든다.
- 다음 등록이 시작되면 타이머가 60초로 다시 초기화된다.
- 전체 배치 실행이 끝나면 타이머가 사라진다.
- 오류가 발생해 실행이 중단되면 타이머가 사라진다.

타이머는 Rust의 실제 대기 시간과 연동된다. Rust가 sleep을 시작할 때 `batch-wait-start` Tauri 이벤트를 프론트엔드로 보내고, 프론트엔드는 그 이벤트를 받아 카운트다운을 표시한다. 가짜 타이머가 아니다.

## Chrome 연결

실행 전 Chrome은 DevTools 포트가 열린 상태여야 한다.

PowerShell에서 Chrome을 실행한다.

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$env:TEMP\pstmacro-chrome-debug"
```

Chrome에서 네이버 로그인을 완료한다.

Windows에서 확인한다.

```powershell
Invoke-WebRequest http://127.0.0.1:9222/json/version -UseBasicParsing
```

WSL에서 확인한다.

```powershell
wsl -d Ubuntu -- bash -lc "curl -sS http://172.24.32.1:9223/json/version | head"
```

화면의 기본 host/port는 현재 환경 기준으로 아래 값이다.

```text
host: 172.24.32.1
port: 9223
```

## 내부 Rust 함수

새 UI에서 사용하는 Rust 함수는 아래 파일에 있다.

```text
src-tauri/src/discussion_batch.rs
```

주요 함수는 다음과 같다.

- `parse_discussion_template_csv`
  - CSV 텍스트를 제목, 내용, 댓글내용 목록으로 파싱한다.
- `search_naver_stocks`
  - 네이버 증권 API에서 종목 후보를 가져온다.
- `run_discussion_batch`
  - 선택한 설정대로 글쓰기/댓글쓰기를 반복 실행한다.
- `validate_batch_request`
  - 필수 입력, 행동 선택, 실행 개수, 선택 모드를 검증한다.
- `pick_text`
  - 랜덤, 순차, 1개만 규칙에 따라 이번 회차에 사용할 문구를 고른다.

```powershell
wsl -d Ubuntu -- bash -lc 'cd ~/projects/pstmacro/src-tauri && source "$HOME/.cargo/env" && cargo test'
```

```powershell
wsl -d Ubuntu -- bash -lc 'cd ~/projects/pstmacro && pnpm test -- --run'
```

프론트 빌드:

```powershell
wsl -d Ubuntu -- bash -lc 'cd ~/projects/pstmacro && pnpm build'
```
