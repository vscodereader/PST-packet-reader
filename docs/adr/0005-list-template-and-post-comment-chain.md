# ADR 0005. CSV 항목은 목록형으로 편집하고 글쓰기+댓글쓰기는 작성 글에 이어서 댓글을 단다

날짜: 2026-05-28

## 상태

Accepted

## 배경

기존 CSV UI는 제목, 내용, 댓글내용 여러 항목을 하나의 텍스트창에 넣고 `---` 줄로 구분했다.

예:

```text
이게되네 ㅋㅋㅋ
---
뭣
```

이 방식은 구현이 단순하지만 일반 사용자가 `---`의 의미를 이해해야 한다.

사용자가 구분선을 지우거나 엔터를 추가하면 항목이 잘못 합쳐질 수 있다.

또한 기존 화면에서는 글쓰기와 댓글쓰기 설정이 항상 같이 보여서 댓글이 어떤 글에 달리는지 기준이 명확하지 않았다.

사수 피드백은 다음과 같았다.

- CSV를 가져왔을 때 제목/내용/댓글내용이 파일 목록처럼 보여야 한다.
- 한 번에 보이는 항목은 최대 5개이고, 더 많으면 드래그/스크롤해서 볼 수 있어야 한다.
- 항목을 선택할 수 있어야 한다.
- 선택한 항목에 대해 랜덤, 순차, 1개만을 적용해야 한다.
- 목록 항목을 더블클릭하면 내용을 수정할 수 있어야 한다.
- 글쓰기만 선택하면 글쓰기 설정만 보여야 한다.
- 댓글쓰기만 선택하면 댓글쓰기 설정만 보여야 한다.
- 글쓰기와 댓글쓰기를 같이 선택하면 먼저 글을 작성하고, 방금 작성한 글에 댓글을 작성해야 한다.
- 작성 개수 3개/5개는 글쓰기 또는 댓글쓰기를 선택했을 때만 보여야 한다.

## 결정

### CSV 항목 표현

CSV 항목을 더 이상 `---` 구분 텍스트로 보여주지 않는다.

제목, 내용, 댓글내용을 각각 목록 UI로 표시한다.

목록은 다음 동작을 제공한다.

- 항목 클릭: 선택/해제
- 항목 더블클릭: 수정 모드
- 수정 저장: 해당 항목 값 교체
- 최대 5개 높이만 표시
- 초과 항목은 목록 내부 스크롤

### 선택 방식

랜덤, 순차, 1개만은 전체 CSV 항목이 아니라 사용자가 선택한 항목 목록에 적용한다.

예:

```text
제목 1
제목 2
제목 3
```

이 중 제목 1과 제목 3만 선택하면 랜덤/순차 대상도 제목 1과 제목 3만 된다.

`1개만`은 선택된 항목이 정확히 1개일 때만 활성화된다.

### 글쓰기/댓글쓰기 화면 분리

작업 체크박스에 따라 화면을 분리한다.

글쓰기만 선택:

```text
글쓰기 설정
- 제목 목록
- 내용 목록
- 제목 모드
- 내용 모드
- 작성 개수
```

댓글쓰기만 선택:

```text
댓글쓰기 설정
- 댓글 내용 목록
- 댓글 모드
- 작성 개수
```

둘 다 선택:

```text
글쓰기 설정
댓글쓰기 설정
작성 개수
```

### 글쓰기+댓글쓰기 실행 순서

둘 다 선택한 경우 Rust 실행 순서를 변경한다.

기존에는 댓글쓰기 실행 시 선택 종목의 토론글 중 하나를 랜덤으로 골랐다.

이제 둘 다 선택한 경우에는 아래 순서로 동작한다.

```text
1. 글쓰기 form 패킷으로 txId 발급
2. 글쓰기 add 패킷 전송
3. add 응답에서 작성 글 ID 확인
4. 작성 글 ID로 토론글 URL 생성
5. 해당 URL 기준으로 댓글 token 패킷 요청
6. 댓글 create 패킷 전송
7. 화면 새로고침
```

즉 프론트 DOM에서 방금 작성한 글을 찾아 클릭하는 방식이 아니다.

Rust 패킷 함수가 글쓰기 응답의 ID를 사용해 직접 작성 글 URL을 만든다.

## 결과

좋은 점:

- 사용자가 `---` 구분선을 이해할 필요가 없다.
- CSV 항목을 파일 목록처럼 보고 고를 수 있다.
- 선택된 항목만 랜덤/순차/1개만 대상이 된다.
- 글쓰기와 댓글쓰기 기준이 명확해진다.
- 글쓰기+댓글쓰기 동시 실행 시 댓글이 랜덤 글이 아니라 방금 작성한 글에 달린다.

주의할 점:

- 목록형 UI 자체는 사용자 입력 화면이므로 프론트에서 처리한다.
- 실제 등록, 댓글 생성, 글 ID 추출은 Rust 패킷 함수에서 처리한다.
- 네이버 글쓰기 add 응답에서 ID 구조가 바뀌면 작성 글 URL 생성 로직도 수정해야 한다.
