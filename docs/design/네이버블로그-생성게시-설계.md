# 네이버 블로그 생성 + 글 게시 — 설계서 (패킷 분석 기반)

패킷: `Desktop/블로그 패킷/네이버 블로그 가입 및 글 게시.pcapng`(새 블로그),
`.../이미 생성된 블로그/이미 만들어진 블로그의 경우.pcapng`(기존 블로그). 둘 다 keylog로 복호화 분석.

## 1. 목표
글쓰기 종류(글/댓글/글+댓글) 옆에 **"네이버 블로그"** 추가. 계정 선택 → (새 블로그면) 블로그명 입력·사용가능 확인 → 발행 설정(공개/발행옵션/카테고리/주제/태그/발행시간) → 게시하기 시 **로그인 후 전부 API(백엔드 HTTP)로** 블로그 생성 + 글 발행. 결과 링크·알림·토스트. **프론트 구동 아님, 게시 전부 API.** pstmacro 먼저, Admin 나중.

## 2. 패킷으로 확인한 API 흐름

### (A) 새 블로그 (nblog4test)
1. 로그인 (`nidlogin.login`, 기존 CDP 로그인 재사용)
2. **블로그명 중복확인**: `GET section.blog.naver.com/blogdomain/BlogDomainDuplicateCheck.naver?domainId=<명>`
   - 응답 JSON(사용가능 여부) — ⚠️ stream 충돌로 원문 미추출, 구현 시 재확인 필요
3. **블로그 생성**: `POST section.blog.naver.com/blogdomain/BlogDomainRegistration.naver`
   - 바디(도메인 등록 필드) — ⚠️ 원문 미추출, 재확인 필요
4. 글쓰기 폼: `GET blog.naver.com/GoBlogWrite.naver` → `PostWriteForm.naver?blogId=<명>&Redirect=Write`
   → `PostWriteFormSeOptions.naver` / `PostWriteFormManagerOptions.naver`(카테고리/공개/발행설정 옵션)
5. 토큰: `POST ncpt.naver.com/v2/tokens?...` + 폼에서 `tokenId` 발급 — ⚠️ 정확 출처 재확인
6. (임시저장) `POST blog.naver.com/RabbitAutoSaveWrite.naver`
7. **글 발행**: `POST blog.naver.com/RabbitWrite.naver` ← 핵심 (§3)
8. 결과: `GET blog.naver.com/PostView.naver?blogId=<명>&logNo=<번호>` → `logNo`=게시글 번호 → 링크

### (B) 기존 블로그 (doselditk12)
1. 로그인
2. **계정의 blogId 조회**: `GET static.nid.naver.com/getProfile?svc=my&callback=...` (또는 계정 저장값)
   → 그 blogId로 **바로 4~8** (명확인·생성 **생략**)
   - 즉 "계정 체크박스 선택 → 그 계정의 기존 블로그명 표시 → 바로 게시"

## 3. 발행 API 원문 (RabbitWrite.naver) — 완전 확보

`POST blog.naver.com/RabbitWrite.naver` · `content-type: application/x-www-form-urlencoded`
헤더: user-agent(Chrome), origin/referer `blog.naver.com`, accept `application/json`, **baggage/sentry-trace**(무시 가능)
쿠키: **BA_DEVICE, NNB, NAC, ASID, NACT** 등 네이버 세션 쿠키(로그인 쿠키 = 재사용)

바디(form) 4개 파라미터:
```
blogId=<블로그명>
&documentModel={ SmartEditor 문서 JSON — 제목 + 내용 }
&mediaResources={"image":[],"video":[],"file":[]}
&populationParams={ 발행 설정 }
&productApiVersion=v1
&tokenId=<write 토큰>
```

### documentModel (제목·내용)
SmartEditor v2.10.2. `document.components[]`:
- `@ctype:"documentTitle"` → title.nodes[].value = **제목**("Testest")
- `@ctype:"text"` → value.nodes[].value = **내용**("nblog4test first write")

### populationParams (발행 UI ↔ 필드 매핑) — 형님이 고른 값 그대로
```
configuration: {
  openType: 2,          // 공개설정: 2=전체공개  (이웃/서로이웃/비공개 값 = ⚠️질문)
  commentYn: true,      // 댓글허용
  sympathyYn: true,     // 공감허용
  searchYn: true,       // 검색허용
  scrapType: 2,         // 블로그/카페 공유(링크 허용)
  outSideAllowYn: true, // 외부 공유 허용
  twitterPostingYn:false, facebookPostingYn:false, cclYn:false
},
populationMeta: {
  categoryId: 1,               // 카테고리(게시판)
  directorySeq: 0,             // 주제(0=주제 선택 안 함)
  postWriteTimeType: "now",    // 발행시간 현재 (예약="reserve" 추정, ⚠️질문)
  tags: "첫글",                 // 태그(콤마 구분 추정)
  noticePostYn: false,         // 공지사항 등록
  continueSaved: true, autoByCategoryYn:false, scrapYn:false, ...
}
```

## 4. UI 설계 (pstmacro publish-modal)
1. 글쓰기 종류 탭에 **"네이버 블로그"** 추가 (글/댓글/글+댓글 옆)
2. 네이버 블로그 선택 화면:
   - 제목 / 내용 입력
   - **게시하기** 누르면 → 계정 선택(체크박스) 화면
   - 계정 선택 시 그 밑에:
     - **새 블로그**: 블로그명 입력칸 + **"사용 가능 확인"** (→ BlogDomainDuplicateCheck 실시간 조회, 결과 표시)
     - **기존 블로그**: 그 계정의 기존 blogId를 **자동 표시**(입력 불필요)
   - 그 밑에 발행 설정 UI(§3 populationParams 그대로):
     공개설정(전체/이웃/서로이웃/비공개) · 발행설정(댓글/공감/검색/공유/외부공유 체크) · 기본값유지 ·
     카테고리 · 주제 · 태그(최대30) · 발행시간(현재/예약) · 공지등록
3. 게시하기 → 백엔드: 로그인 → (새 블로그면 명확인·생성) → RabbitWrite 발행 → 결과 링크

## 5. 재사용 vs 신규
- **재사용**: 네이버 로그인(CDP)·쿠키 저장(`cookies/{id}.json`)·`naver_blog/headers.rs`(블로그 위장 헤더)·`error.rs`·백트레이스(게시 실패 trace, 기존 패턴)·결과 알림/토스트/링크(기존 게시 결과 UI)·원문 로그(패킷 원문 로그 기존 패턴)
- **신규(naver_blog에 추가)**: `BlogDomainDuplicateCheck`(명확인)·`BlogDomainRegistration`(생성)·`RabbitWrite`(발행: documentModel/populationParams 빌더)·tokenId 발급·기존 blogId 조회(getProfile)
- 기존 `naver_blog/`엔 **댓글(comment_client)·post_list만** 있음 → 위 4개는 전부 신규

## 6. 로깅 / 백트레이스 / 결과 (형님 필수 요구)
- **로그에 와이어샤크와 동일한 원문**: 요청 URL·헤더·바디·응답 status·바디를 **필터링 없이 원문 그대로** (실패 원인 추적용). 기존 "게시 API 응답 원문 로그"(c37c20b) 패턴 재사용·확장
- **백트레이스 연결**: 블로그 게시 실패 시 backtrace → 알림 "자세히 보기" (기존 재사용)
- **결과**: 게시 성공 시 게시 링크(`blog.naver.com/<명>/<logNo>`) + 알림 페이지 + 토스트

## 7. 확인 필요 (형님께 질문 — §아래)
1. 공개설정 openType 값: 전체공개=2 확인. **이웃공개/서로이웃공개/비공개**의 값?
2. 발행시간 예약 시 값(`postWriteTimeType`="reserve"? 예약시각 필드?) — 지금은 "현재"만 필요하면 스킵
3. 카테고리/주제: 새 블로그는 categoryId=1(기본)/directorySeq=0(주제없음)으로 충분? 아니면 선택 UI 필요?
