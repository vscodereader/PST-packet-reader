# 블로그 "글쓰기(새 글 발행)" 원격배포 — 결정 필요 문서

> 작성: 2026-07-13 야간 작업 중. 이 문서는 **구현이 아니라 결정을 위한 자료**다.
> 요청은 "Admin에 블로그 글쓰기 원격배포를 넣고, DB 미연결 항목을 전부 연결하라"였다.
> DB 미연결 3건은 밤새 구현했으나(아래 §6), **블로그 글쓰기 원격배포는 설계·패킷 상의
> blocker가 있어 배선하지 않고 이 문서로 남긴다.** "무턱대고 배선하지 말고 설계부터
> 확인하라"는 지시에 따른 결과다.

## 1. 요청한 것

- pstmacro 데스크톱에 이미 만든 **블로그 새 글 발행 UI/코드**(`src/features/blog/blog.tsx`,
  `src-tauri/src/naver_blog/write_client.rs`, Tauri `blog_publish`)를 **그대로 재사용**해서
- **Admin → 서버 → 하위(com)** 원격배포 경로에 올려, 관리자가 원격으로 블로그 새 글을
  발행하게 한다.
- 사진/파일/글꼴 등 첨부도 UI 그대로 동작하게.

## 2. 설계 정본이 규정한 것 (핵심 충돌)

`docs/Admin UI/11-블로그-분배와-게시.md` 는 **블로그를 "댓글 전용"으로 명시**한다:

> "블로그는 댓글 전용이다(글쓰기 없음)."
> "분배 때 로그인해 쿠키를 확보해 두고, 게시(댓글) 시점엔 그 쿠키로 바로 댓글을 단다."

즉 **현재 설계 정본에는 "블로그 새 글 발행"의 원격배포 구조가 존재하지 않는다.**
새 글 발행은 별도 문서 `docs/design/네이버블로그-생성게시-설계.md`(패킷분석 기초, **미구현**)로만
있다. 그래서 지금 Admin에 글쓰기를 배선하면 **정본 설계 규칙을 벗어난 신규 아키텍처를
임의로 만드는 것**이 된다 → 사수 확인 없이 진행하면 안 되는 영역.

## 4. 패킷 현실 (구현 불가 지점)

`/home/csw/packet_copy/블로그 패킷` 4개 캡처(가입+글게시 / 이미 만든 블로그 / 예약+공개범위 /
닉네임)를 전부 복호화·분석한 결과:

- **`multipart/form-data` = 4개 캡처 모두 0건.** → **실제 사진/파일 업로드 트랜잭션이
  하나도 안 잡혔다.** `blogfiles.naver.net` 호출은 전부 기존 썸네일 _조회_(dthumb)일 뿐.
- 따라서 **사진/파일/글꼴 업로드는 지금 패킷으로 구현할 근거가 없다.**
- 반면 **텍스트 발행·공개범위(openType)·예약(prePost\*)·태그·댓글/공감/검색 설정은 패킷에
  다 있어 구현 가능**하다(이미 데스크톱 로컬에 구현됨).

→ **필요 조치: 회사에서 "사진 첨부하며 글 발행"을 다시 캡처**해야 이미지/파일 업로드를
실제 API로 붙일 수 있다.

## 5. 선택지 (권장 순)

### 옵션 A — 텍스트 새 글 발행만 원격배포 (권장, 부분)

데스크톱 로컬 발행 로직을 재사용해 **글자/공개범위/예약/태그까지만** 원격배포. 사진/파일/글꼴은
자리만(비활성 or "내일 캡처 후") 둔다.

- 작업량: **중~대**. 밴드 게시 큐 모델(`band_publish`) 미러링 필요:
  - 서버: 새 명령 스펙 `PublishBlogWrite`(title/content/openType/reserve/tags…) + `dispatch`
  - 하위: `PublishCmd`에 새 필드 + `build_blog_write_items` + `queue_runner`에 `run_blog_write_targets`(신규 — `publish_blog_post_for_account` 호출)
  - Admin: 새 글쓰기 폼(데스크톱 `blog.tsx` UI 재사용)
  - 결과보고: `PlatformId::Blog` 통합 모델 재사용
- blocker: 없음(텍스트 한정). 단 **설계 정본에 없는 신규 구조**라 사수 승인 필요.

### 옵션 B — 완전한 글쓰기(사진/파일/글꼴 포함) 원격배포

- blocker: **업로드 패킷 부재**로 지금 불가. 캡처 재확보 후에만.

### 옵션 C — 설계 정본대로 "블로그 댓글" 분배·게시부터 배선

`11-블로그-분배와-게시.md` 그대로 ADD-ONLY 구현(엔진 무손상, `plan.blog`만 조립).

- 요청("글쓰기")과는 다르지만 **설계와 100% 일치**하고 가장 안전.

## 6. 이 브랜치에서 실제로 한 것 (밤새)

- **DB 미연결 3건 영속화**(서버 크레이트): `scheduled_posts`(예약게시=배포 blocker) /
  `stop_reports`(중지리포트) / `daily_results`(날짜집계). write-through + 부팅 rehydrate.
  → 서버 재시작해도 예약/중지/집계가 유지된다. (상세는 커밋 로그 참조)
- band_auth 쿠키 신선도 게이트 커밋(별개 선반영분).
- **블로그 글쓰기 원격배포는 §2·§4 사유로 배선하지 않음** — 본 문서로 결정 대기.
