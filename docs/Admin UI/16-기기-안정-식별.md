# 16. 하위 기기 안정 식별 (같은 PC = 같은 기기) — #441

- 근거: HANDOFF §E 설계
- 코드(서버): `server/src/routes.rs`(`register_device`) · `server/src/repo/*`(`find_device_by_machine_id`/`set_device_name`) · `server/src/model.rs`(`Device.machine_id`/`RegisterReq.machine_id`) · `server/migrations/0001_init.sql`
- 코드(하위 앱): `src-tauri/src/agent/mod.rs`(`agent_register`/`machine_ident`) · `src-tauri/src/agent/net.rs`(`RegisterReq.machine_id`)

## 문제

같은 하위 PC를 기기코드로 재등록/재설치할 때마다 **서버가 새 랜덤 UUID로 `하위-xxxx`를 새로
만든다**. 등록 기준이 "기기"가 아니라 "일회용 기기코드"라 중복검사가 없다. → 같은 컴퓨터가
매번 다른 기기로 늘어나 기기목록·결과보고·통신로그가 뻥튀기된다.

(평소엔 안 바뀌는 이유: 하위 앱이 토큰·이름을 `agent.json`에 저장해 재시작 땐 재연결만 한다.
이름이 바뀌는 건 **재설치/등록해제/새 기기코드** 로 실제 재등록이 일어날 때뿐.)

## 해결 (기존 코드 무손대·추가/분기만)

### A. 컴퓨터 이름 표시

하위 앱이 등록 시 **컴퓨터 이름**을 name으로 전송한다.

- 소스: Windows `COMPUTERNAME` → `HOSTNAME` → `hostname` 명령 폴백(`machine_ident::computer_name`).
- 서버는 이미 `req.name`을 존중하므로 **서버 로직 변경 없이** 이름이 반영된다.
- 못 구하면(비Windows 등) 서버 생성 규칙과 동일한 `하위-XXXX`로 폴백.

### C. machine_id upsert (재설치에도 같은 기기)

하위 앱이 **기기 고유값**을 `machine_id`로 함께 전송한다.

- 소스: Windows 레지스트리 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`(`/reg:64`),
  비Windows(개발/서버)는 `/etc/machine-id`(`machine_ident::machine_guid`). OS 설치 단위로 고정 →
  **앱 재설치와 무관**(← `agent.json`은 재설치 때 지워지므로 부적합).
- 서버 `devices`에 `machine_id TEXT`(nullable) 컬럼 추가. `register_device`를 **upsert**로:
  machine_id로 기존 기기를 찾으면 → **같은 `device_id` 재사용 · 이름/last_seen 갱신 · 토큰
  재발급**(새 row를 만들지 않음). 없으면 신규 생성.
- **하위호환**: `machine_id`가 nullable → 옛 앱(미전송)·옛 row(NULL)는 기존처럼 신규 생성 폴백.
- 기기코드는 여전히 1회용(재등록도 새 코드 필요). upsert는 코드 소비 **후** 판정한다.

## 보안·봇탐지 영향 0

hostname·MachineGuid는 **우리 중앙 서버로만** 전송(우리 API). 네이버·밴드 요청/크롬 흐름에는
주입되지 않는다. 봇탐지는 CDP 크롬 지문·IP·캡차 위험점수·키입력 품질로 판정 — 기기 등록
식별자와 무관한 층. MachineGuid는 로컬 레지스트리 read일 뿐.

## GCP 영향

다음 배포(`gcloud run deploy pstmacro-server --source .`) 시 새 서버 스타트업이
`ALTER TABLE devices ADD COLUMN IF NOT EXISTS machine_id TEXT`를 기존 Cloud SQL 연결로 1회
멱등 실행(안전). **수동 psql/ALTER 불필요.** 시크릿·포트·공개범위·보안정책 무변경.

## 통신로그(#440)와의 관계

감사로그의 `device` 필터 키는 **`device_id`(UUID)** 다(이름은 `dir`에만). 안정 식별 후에는 같은
PC가 같은 UUID를 유지하므로 통신로그의 "컴퓨터" 목록이 안정된다. 통신로그 3단 필터(#440)는
이 UUID를 `/devices`의 **실제 이름**으로 표시하도록 맞춘다(#440에서 라벨 해석 반영).

## 확인 방법

- 서버 단위테스트: `register_same_machine_id_reuses_device`(같은 machine_id 2회 → 기기 1개·같은
  id·이름 갱신), `register_different_machine_id_creates_new_device`, `register_without_machine_id_falls_back_to_new_row`.
- 실기기: 같은 PC에서 등록해제 후 재등록(또는 재설치) → 기기목록에 **1대**로 유지되고 이름이
  실제 컴퓨터 이름으로 표시되는지.
