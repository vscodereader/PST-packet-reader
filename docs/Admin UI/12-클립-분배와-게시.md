# 12. 네이버 클립 — 계정 분배 + 게시 명령 (Admin)

> 카페(10)·블로그(11) 문서의 형제. 배선 구현 완료(설계+구현).
>
> **대원칙:** 클립 기능(로그인·프로필 생성·최신 N개 조회·댓글 작성)은 **이미 하위(com pstmacro)에
> 전부 구현돼 있습니다.** 그러니 **기존 클립 엔진과 기존 데스크톱 UI를 한 줄도 고치지 않고 그대로
> 재사용**하고, Admin은 "이 창작자의 최신 미디어에 이 계정으로 댓글을 달아라"는 **명령만** 내려보냅니다.
> **없는 배선(Admin UI + 명령 스키마 + 하위 조립)만 새로 만들고, 있는 것은 절대 새로 만들지 않습니다.**
> 아래 **§1 재사용 지점**에 "무엇을·어디서(`file:line`)·어떻게" 재사용하는지 전부 적어 두었습니다.

## 0. 한눈에

**클립은 댓글 전용**입니다(글쓰기 없음 — `naver_clip/mod.rs:2` 머리말: "동일한 저장 쿠키를 그대로
재사용"). **블로그와 취급이 똑같습니다** — 별도 로그인 흐름이 없고 **저장된 네이버 쿠키**
(`cookies/{loginId}.json`)를 재사용해 댓글을 답니다. 그래서 카페와 달리 **분배 때 네이버 로그인**해
쿠키를 확보해 두고(종토·블로그와 동일), 게시(댓글) 시점엔 그 쿠키로 바로 댓글을 답니다.

댓글 대상은 **한 가지 모드**뿐입니다 — **창작자(@handle)의 최신 미디어 N개**:

| 입력(링크) | 동작 |
|---|---|
| 창작자 링크 `https://clip.naver.com/@<handle>` | 그 창작자의 **최신 미디어 N개**에 각각 댓글 1개 |
| `…/@<handle>?tab=video` | **영상만** 대상(그 외/`?tab=all`=전체) |

> ℹ️ 클립은 "특정 영상 1건"이나 "인기 정렬" 모드가 없습니다(엔진에 없음). 항상 **창작자 최신 N개**입니다.
> N은 데스크톱에선 글(댓글 템플릿)의 `commentCount`로 동결되며(`publish-modal.tsx:595`),
> Admin은 블로그와 동일하게 **"개수 N" 입력칸(이미 존재)** 을 재사용해 운영자가 지정합니다.

> ⚠️ **본인인증**: 클립 댓글은 계정이 **본인인증(실명·연령)** 을 마쳐야 합니다. 미인증 계정은 프로필
> 생성 단계에서 **`SignUp code=-7020`** 으로 실패합니다(`naver_clip/profile.rs:166`, "코드로 우회
> 불가"). 이는 **런타임 계정 속성**이라 Admin 배선의 대상이 아니며, 결과보고에 실패로 그대로 뜹니다(§6).

Admin은 블로그와 **동일한 UX**(창작자 링크 입력 → 칩 목록)를 이식하고, `지금 게시`/`예약 게시`를
누르면 그 명령이 하위로 내려가 하위 큐 러너가 저장 쿠키로 최신 N개에 댓글을 답니다.

## 2. 계정 분배 — 플랫폼 열 + 클립 = 로그인해서 등록 (블로그와 동일)

- **UI**(`src/admin/features/account-distribute/account-distribute.tsx`): 카페·블로그와 **동일한
  플랫폼 Select**에 `네이버 클립`(`clip`)을 노출(이미 `PlatformId::Clip`·`platform_from_str("clip")`
  존재). 아이디/비밀번호/휴지통. — **이미 `PLATFORMS`에 클립이 있으므로 새 옵션 추가 불필요.**
- **명령 경로**: `import`(스테이징)에 `platform:"clip"`을 실어 보냄 → 서버 `StagedAccount.platform`
  → 분배 payload `{loginId, pw, platform:"clip"}` → 하위 `AccountIn.platform`.
- **하위 등록/로그인 분기**(`src-tauri/src/agent/mod.rs distribute_accounts`:487): 클립은 **카페가 아님**
  (`is_cafe_platform("clip")==false` :101)이라 **종토·블로그와 동일하게 분배 직후 자동 로그인**
  (`enqueue_login`)합니다 → 그래야 `cookies/{loginId}.json`이 생겨 게시 시점에 그 쿠키로 댓글을 답니다.
  클립 로그인은 **네이버 로그인**이라(밴드처럼 별도 로그인 아님) **현재 `enqueue_login`이
  `platform: PlatformId::Naver`로 태우는 것(`agent/mod.rs:1244`)이 그대로 맞습니다 — 손댈 것 없음.**

> **결론:** 클립의 계정 취급 = **블로그와 100% 동일**(분배 시 네이버 로그인, 로그인 성공만 게시 대상).
> 링크 입력 UX만 창작자 핸들로 바뀝니다.

## 3. 게시 명령 — 클립 창작자 링크(최신 N개)

- **UI**(`publish-command.tsx`): 현재 `TARGETS`에 클립이 없으므로 **클립 항목 추가 + `ClipConfig`
  렌더**(블로그 `BlogConfig`:1590 형제). 클립은 **댓글 전용**이라 `kind==="comment"`일 때만 활성.
  - `창작자 링크` 입력 + `추가` → **`parseClipLink`(재사용)** 으로 `{handle, mediaType?}` 파싱해 칩에 누적.
  - `개수(N)` 입력 — **블로그 최신 N개 NumberInput 그대로 재사용**(`BlogConfig`의 `count`). 없으면 1.
  - 칩에 `@handle · 영상만`/`@handle` 표시(데스크톱 `publish-modal.tsx:618` 라벨 동일). 제거 X 포함.
  - 계정 = **이 하위의 클립(`clip`) 계정 중 로그인 성공(active)** (쿠키 필요 — 블로그와 동일 규칙).
- **명령 경로**: `publish.send`/`scheduled.create`에 `target:"clip"` + `clipLinks:[{handle, mediaType?, count?, link}]`
  추가 → 서버 `PublishSpec.target`/`clip_links`(신규, `PublishBlogLink`:80 형제) → payload → 하위 `PublishCmd`.

## 4. 클립 계정 노출

- Admin `accountsFor`(`publish-command.tsx:288`)에 **클립 분기** 추가: `target==="clip"`이면 인벤토리의
  **platform==clip 계정 중 active**만(블로그와 동일 — 쿠키 필요). 카페(`accountRows` 전부)와 다릅니다.

## 6. 범위 · 비범위

- **이번 범위**: 클립 **댓글**(창작자 최신 N개)을 Admin 명령으로. UI는 블로그와 동일한 링크→칩 UX.
  계정 취급은 블로그와 동일(분배 시 네이버 로그인, active만 게시).
- **비범위(엔진에 없음/런타임)**:
  - **특정 영상 1건·인기 정렬** — 엔진에 없음(항상 창작자 최신 N개).
  - **본인인증(-7020)** — 계정 런타임 속성. 미인증 계정은 프로필 생성 실패로 결과보고에 그대로 뜸(우회 불가). Admin 배선 대상 아님.
  - **클립/블로그/카페/밴드·클립 엔진 수정** — 없음. 오직 Admin↔서버↔하위 **조립 배선만** 신규.
- **실기기/실서버 검증은 사수/사용자 몫**(이 환경엔 폰·네이버 로그인·본인인증 계정 불가).
