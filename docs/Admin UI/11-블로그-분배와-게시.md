# 11. 네이버 블로그 — 계정 분배 + 게시 명령 (Admin)

> 요구: Admin에서 명령을 내리면 하위 COM이 실행한다. 원칙은 **기존 블로그 엔진을 한 줄도
> 고치지 않고 그대로 재사용**하고, Admin은 "이 블로그(글/최신)에 이 계정으로 댓글을 달아라"는
> **명령만** 내려보낸다. 없는 배선(Admin UI + 명령 스키마 + 하위 조립)만 새로 만들고, 무관
> 코드(카페/밴드/종토·블로그 엔진)는 안 건드린다. 카페 문서([10-카페-분배와-게시](./10-카페-분배와-게시.md))의
> 형제 문서다.

## 0. 한눈에

**블로그는 댓글 전용**이다(글쓰기 없음 — `naver_blog/mod.rs` 머리말: "블로그는 댓글 전용").
별도 로그인 흐름이 없고 **저장된 네이버 쿠키**(`cookies/{loginId}.json`)를 그대로 재사용해
댓글을 단다. 그래서 카페와 달리 **분배 때 로그인**해 쿠키를 확보해 두고(종토·밴드와 동일),
게시(댓글) 시점엔 그 쿠키로 바로 댓글을 단다.

댓글 대상은 **두 가지 모드**뿐이다(데스크톱과 동일):

| 모드 | 입력(링크) | 동작 |
|---|---|---|
| **특정 게시글** | 글 URL (`blog.naver.com/{blogId}/{logNo}`) | 그 글 하나에 댓글 |
| **최신글 / 인기글** | 블로그 홈 URL (`blog.naver.com/{blogId}`) | 그 블로그 **최신 N개** 글에 댓글 |

> ⚠️ **"최신글"과 "인기글"은 동일 동작**이다 — 데스크톱(`publish-modal.tsx:269·446`)에서 둘 다
> `blogIsListTarget=true`로, 블로그 홈 링크에서 `blogId`를 뽑아 **최신 N개**를 조회해 댓글을 단다.
> 블로그 백엔드에는 별도 "인기 정렬" 조회가 없다(`post_list.rs`=`fetch_latest_posts` 한 종류).
> UI 라벨만 "최신/인기"로 나뉘고 실동작은 같다(사용자 확인 완료).

Admin은 카페와 **동일한 UX**(링크 입력 → 목록 → 선택 배지)를 이식하고, `지금 게시`/`예약 게시`를
누르면 그 명령이 하위로 내려가 하위 큐 러너가 저장 쿠키로 댓글을 단다.

## 1. 재사용 지점 (코드에 이미 있음 — 그대로 씀)

| 무엇 | 위치 | 재사용 방식 |
|---|---|---|

| 계정 모델(플랫폼 보유) | `src-tauri/src/ipc/accounts.rs` `Account.platform` (`PlatformId::Blog`) | 필드 이미 있음. |
| 블로그 **글 링크** 파싱(특정글) | `src/features/posts/publish-helpers.ts` `parseBlogPostLink`(→`{blogId, logNo}`) | Admin에서 그대로 import. **네트워크 불필요**(순수 파싱). |
| 블로그 **홈 링크** 파싱(최신 N) | `src/features/posts/publish-helpers.ts` `parseBlogLink`(→`{blogId, categoryNo?}`) | 동상. |
| 블로그 게시 대상 | `src-tauri/src/ipc/queue.rs` `BlogTarget{account_id, name, blog_id, log_no, link, count?, category_no?}`(:128), `plan.blog`(:215) | 하위 에이전트가 이 구조로 `plan.blog`를 조립. |
| 블로그 댓글 엔진(쿠키 재사용·특정글·최신N) | `src-tauri/src/naver_blog/{mod.rs,comment_client.rs,post_list.rs}` → `queue_runner.rs run_blog_targets` | **한 줄도 안 고침.** `plan.blog`만 채우면 큐 러너가 저장 쿠키로 특정글/최신N 댓글을 전부 수행. |
| 데스크톱 블로그 UI(링크→목록→배지·모드전환) | `src/features/posts/publish-modal.tsx`(`resolvedBlogs`/`blogHomes`/`blogLink`/`blogHomeLink`/`blogIsListTarget`) | Admin에 동일 UX 이식. |
| 댓글 내용/개수 | 글(`count`=최신 N개, 특정글=1건)에 **동결** | 게시명령이 링크·개수·내용만 정하고, 엔진이 대상 글을 조회해 처리(데스크톱과 동일). |

## 2. 계정 분배 — 플랫폼 열 + 블로그=로그인해서 등록

- **UI**(`src/admin/features/account-distribute/account-distribute.tsx`): 카페와 동일한 **플랫폼
  Select**에 `네이버 블로그`(`blog`)를 노출한다(이미 `PlatformId::Blog` 존재). 아이디/비밀번호/휴지통.
- **명령 경로**: `import`(스테이징)에 `platform:"blog"`를 실어 보낸다 → 서버 `StagedAccount.platform`
  → 분배 payload `{loginId, pw, platform:"blog"}` → 하위 `AccountIn.platform`.
- **하위 등록/로그인 분기**(`src-tauri/src/agent/mod.rs distribute_accounts`): 블로그는 **카페가 아님**
  (`is_cafe_platform("blog")==false`)이라 **종토·밴드와 동일하게 분배 직후 자동 로그인**(`enqueue_login`)
  한다. → 그래야 `cookies/{loginId}.json`이 생겨 게시(댓글) 시점에 그 쿠키로 바로 댓글을 단다.
  (카페만 "등록만·게시 순간 로그인"의 예외다.)

> **결론:** 블로그의 계정 취급 = **종토와 동일**(분배 시 로그인, 로그인 성공만 게시 대상).
> 링크 입력 UX만 카페를 닮는다.

## 3. 게시 명령 — 블로그 링크(특정글 / 최신·인기)

- **UI**(`src/admin/features/publish-command/publish-command.tsx`): 현재 블로그는
  `TARGETS`에서 `{ key:"blog", label:"네이버블로그", soon:true }`(:64)로 **버튼만 있고 비활성**이다.
  이 문서의 작업 = **`soon:false`로 열고 `BlogConfig`를 렌더**한다(카페 `CafeConfig` 형제):
  - **모드 토글**: `특정 게시글` ↔ `최신글/인기글`(데스크톱 `blogIsListTarget`과 동일).
  - `특정 게시글`: `글 링크` 입력 + `추가` → `parseBlogPostLink`로 `{blogId, logNo}` 파싱해 목록 누적.
  - `최신글/인기글`: `블로그 링크` 입력 + `추가` → `parseBlogLink`로 `{blogId, categoryNo?}` 파싱 +
    **개수(N)** 입력. 여러 링크 → 여러 블로그 다중 선택.
  - Select → 고른 항목이 아래 **동그라미 배지**(제거 X 포함). **데스크톱 publish-modal 블로그 카드와 동일.**
  - 계정 = **이 하위의 블로그(`blog`) 계정 중 로그인 성공(Active)**(쿠키가 있어야 댓글 가능 — 종토와 동일 규칙).
- **명령 경로**: `publish.send`/`scheduled.create`에 `target:"blog"` + `blogLinks:[{blogId, logNo?, categoryNo?, count?}]`
  추가 → 서버 `PublishSpec.target`/`blog_links`(신규) → payload → 하위 `PublishCmd`.

## 4. 블로그 계정 노출

- Admin `accountsFor`(`publish-command.tsx:284`)에 **블로그 분기** 추가: `target==="blog"`이면
  인벤토리의 **platform==blog 계정 중 Active**만(종토와 동일 — 쿠키 필요). 카페(`accountRows` 전부)와 다르다.
- 인벤토리 보고는 기존 `accounts`(Active) 그대로 재사용 가능(블로그도 Active만 쓰므로 신규 필드 불필요).

## 5. 구현 체크리스트 (없는 배선만 신규 — ADD ONLY)

**프론트(Admin)**
1. `publish-command.tsx`: `blog` 타깃 `soon:false`로 활성화 + `BlogConfig` 컴포넌트(카페 `CafeConfig` 복제·개조).
2. `accountsFor`에 `target==="blog"` → platform==blog·Active 분기.
3. `publish.send`/`scheduled.create` payload에 `target:"blog"`·`blogLinks` 직렬화. `parseBlogPostLink`/`parseBlogLink`는 이미 있음.

**서버(server/)**

**하위(에이전트)**
6. `src-tauri/src/agent/mod.rs` `PublishCmd`(:124)에 `blog_links: Vec<BlogLinkIn>` 추가.
7. 대상 분기(:677 `if p.target == "naver"`)에 **`else if p.target == "blog"` → `build_blog_publish_items`** 추가(카페 `build_naver_publish_items`(:871) 형제):

## 6. 범위 · 비범위

- **이번 범위**: 블로그 **댓글**(특정 게시글 / 최신·인기=최신 N개)을 Admin 명령으로. UI는 카페와 동일한
  링크→목록→배지 UX. 계정 취급은 종토와 동일(분배 시 로그인, Active만 게시).
- **비범위(추후/설계상 없음)**:
  - **블로그 글쓰기** — 블로그 엔진 자체가 댓글 전용이라 글쓰기 명령은 이번 범위 밖(요구도 댓글 중심).
  - **인기 전용 정렬** — 블로그 백엔드에 없음. "인기글"은 "최신 N개"와 동일 경로로 동작(위 0절 주의).
  - **카페/밴드/종토·블로그 엔진 수정** — 없음. 오직 Admin↔서버↔하위 조립 배선만 신규.
- **실기기/실서버 검증은 사수/사용자 몫**(이 환경엔 폰·네이버 로그인 불가).
