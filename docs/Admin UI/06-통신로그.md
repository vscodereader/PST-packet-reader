# 06. 통신 로그 화면

- 설계서 근거: `설계.md` §10-5 (감사로그 콘솔 + 내보내기), §7 감사로그, §4 상태
- 코드: `src/admin/features/comm-log/comm-log.tsx`
- 위치: 사이드바 "비밀번호 변경" 아래
- 상태: UI만 (더미 로그)

## 무엇을 보여주나

**모든 컴퓨터(하위)의 Admin↔하위 통신**을 콘솔(PowerShell/명령창 스타일)로 한 곳에서:

- `[CMD]` Admin → 하위 명령 — **무엇을 보냈는지 인자까지**(distribute=몇 건·어느 계정, delete=어느 ID·사유) + commandId + operator
- `[RESULT]` 하위 → Admin 결과 — **계정별 한 줄씩**(어느 ID가 성공/보류/실패 + 사유) + 배치 집계
- `[HEARTBEAT]` 주기적 "살아있음 + 현재 IP" / `[STATE]` ROTATING 등 §4 상태(IP 회전 시작 시 기존 IP)
- `[SSE]` / `[REGISTER]` 연결·끊김·재연결(**기존 IP → 바뀐 IP**)·기기등록·토큰발급
- `[REJECT]` 거부된 명령 — `device_name`(대상 컴퓨터)·`명령`(타입+한글, 예 `import_then_login_all(전체로그인)`)·`commandId`(추적번호, 기기이름 아님)·`사유`(예 대상 꺼짐 offline·거부코드 409)·`operator`·`src`(핸들러 절대경로:줄, 미구현이라 현재 예정 위치) (§4-2·§10-5)

## 형식

- 한 줄 = `시각  [태그]  방향  메시지` (모노스페이스, 어두운 배경).
- 색: CMD=파랑 / 결과·성공=청록 / 실패·REJECT=빨강 / 경고=노랑 / 정보=회색.
- **표시 정책(운영자 결정)**: **통신 로그에 한해 ID·PW를 마스킹 없이 평문 표시**(어느 ID/PW로 로그인했고 결과가 뭔지 추적용). 결과 보고 등 다른 화면은 마스킹(앞 2글자+`•`) 유지. ⚠️ PW가 서버 DB·화면·`.txt`에 평문으로 남으니 접근통제·내보내기 취급 주의(§10-5·§12). 로컬 tracing(`logging.rs`)은 그대로 PW 미로깅.
- **함축 금지**: 집계만(`3/10`) 찍지 않고 계정별 결과·삭제 대상 ID·사유·IP 기존→바뀐을 모두 남긴다(§10-5 "로그 상세 규칙").

## 일자별 필터 (3단 종속 목록형) — #439

로그가 날짜 구분 없이 계속 쌓이므로, **컴퓨터 → 날짜**로 좁혀 볼 수 있게 필터를 3개의
종속 드롭다운으로 확장한다. (기존 "전체/특정 하위" 1단 필터를 대체.)

- **목록1 (컴퓨터)**: `Admin(전체)` · 하위COM들. (시스템 로그는 여기 안 나오고 목록2에서 고름.)
- **목록2**:
  - 목록1 = **특정 하위COM** → 그 COM이 **기록을 가진 날짜만** 최신순으로 표시(기록 없는
    날짜는 나오지 않음). 이때 목록3은 비활성.
  - 목록1 = **Admin** → `시스템` · 하위COM들 (컴퓨터를 다시 고르는 목록).
- **목록3** (평소 **비활성**): 목록1 = Admin **그리고** 목록2 = 하위COM 일 때만 활성 →
  그 COM의 날짜 목록. (하위COM을 직접 고른 경로가 막힐 때를 대비한 예비 경로 — 같은
  "COM+날짜" 결과에 도달한다.)

**필터 결과**

| 목록1   | 목록2   | 목록3  | 보이는 로그                  |
| ------- | ------- | ------ | ---------------------------- |
| Admin   | (없음)  | —      | 전체                         |
| Admin   | 시스템  | 비활성 | 시스템 로그(device 미지정)만 |
| Admin   | 하위COM | (없음) | 그 COM 전체                  |
| Admin   | 하위COM | 날짜   | 그 COM의 그 날짜만           |
| 하위COM | (없음)  | —      | 그 COM 전체                  |
| 하위COM | 날짜    | —      | 그 COM의 그 날짜만           |

- 목록1을 바꾸면 목록2·3이, 목록2를 바꾸면 목록3이 초기화된다(종속 드롭다운).
- **[내보내기]** 는 현재 필터가 적용된 로그만 `.txt`로 저장한다(일자별 저장 가능).
- **컴퓨터 라벨 = 실제 이름(#441).** 감사로그의 `device`는 `device_id`(UUID)라, 목록1·목록2의
  컴퓨터는 `/devices`(`api.devices.list`)의 실제 컴퓨터 이름으로 표시한다(`deviceLabel`). 기기
  안정 식별(#441)로 같은 PC가 같은 device_id를 유지하므로 목록이 안정된다. 레지스트리에 없으면
  UUID 앞 8자리, 더미(미리보기)는 원문.

**날짜 기준 = KST(UTC+9).** 서버 감사로그 `ts`는 UTC ISO(`Utc::now().to_rfc3339()`)로
내려오므로, 날짜 추출·화면 표시 모두 KST로 변환한다 — 서버의 결과보고 일자집계
(`server/src/state.rs`, KST 버킷)와 같은 기준이라 **자정 근처 로그가 엉뚱한 날짜로 새지
않는다.** 순수 로직은 `comm-log-filter.ts`로 분리해 단위테스트(`comm-log-filter.test.ts`).

## 내보내기

- 화면 위 **[내보내기]** 버튼 → 로그를 **`.txt`** 파일로 저장.
- 웹이라 브라우저 다운로드(Blob)로 저장(§8 데스크톱 전용 호출의 웹 대체).

## 확인 방법

`pnpm dev` → admin.html → 사이드바 "통신 로그".

- 콘솔에 더미 통신 로그(명령·결과·하트비트·IP변경) 18줄.
- 상단 [내보내기]로 `comm-log.txt` 다운로드.
- 3단 필터: 목록1에서 하위COM 선택 → 목록2에 그 COM의 날짜만 표시 / 목록1=Admin →
  목록2=컴퓨터, 하위COM 고르면 목록3(날짜) 활성.
