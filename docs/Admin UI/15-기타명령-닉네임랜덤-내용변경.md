# 📐 설계서: 기타 명령 페이지 + 게시 옵션(닉네임 랜덤·게시 후 내용변경) — Admin 이식

> **대원칙:** 이 5개 기능은 **데스크톱(하위 com/pstmacro)에 이미 전부 구현**돼 있다. Admin은 UI를
> 이식하고 **명령만 내려보내며**, 실제 실행은 하위 에이전트가 **기존 데스크톱 엔진을 그대로 호출**한다.
> **없는 배선만 새로 만들고, 있는 것은 절대 새로 만들지 않는다.** (카페/밴드 게시명령을 이식한 방식과 동일.)

대상 5개:
1. **기타 명령** 페이지(신규): 좋아요 / 싫어요 / 조회수 / IP 변경
2. **게시 명령** 확장: 종토 댓글에 **닉네임 랜덤** 체크박스
3. **게시 명령** 확장: 종토 글에 **게시 후 내용변경** 체크박스

---

## 2. 기타 명령 페이지 (신규)

### 2-1. 네비 위치
`screens.ts`의 `Screen` union에 `"etc-command"` 추가, `PREVIEW_SCREENS`에서 **`scheduled-posts`(예약된 글) 바로 다음**에 `{ value: "etc-command", label: "기타 명령", group: "앱(로그인 후)" }`. 라우팅은 `admin-app.tsx`에 케이스 추가.

### 2-2. 흐름
1. **하위 컴퓨터 선택** — 게시명령과 동일(온라인 기기 목록에서 1대 선택). `publish-command`의 기기 선택 UI 재사용.
2. 하위를 고르면 **"행동을 고르세요"** 목록형 버튼(SegmentedControl/버튼 그룹) 활성화 → **좋아요 / 싫어요 / 조회수 / IP 변경** 4개.
3. 고른 행동에 따라 하단 UI 전환:
   - **좋아요 / 싫어요**: `LikeModal` UI 이식 — 링크 입력(여러 개) + **그 하위의 종토 계정** 체크박스 선택 → [좋아요]/[싫어요] 버튼.
   - **조회수**: `ViewCountModal` UI 이식 — 링크 입력(여러 개) + **횟수 N**(1~상한) → [조회수] 버튼. 계정 없음.
   - **IP 변경**: [IP 변경] 버튼 하나 → 누르면 **그 하위 PC만** IP 회전.

### 2-3. 명령 경로 (신규 배선)
Admin → 서버 → SSE → **에이전트 새 핸들러** → 데스크톱 엔진 직접 호출.

| 행동 | 새 명령 kind | 에이전트가 호출할 기존 엔진 | 페이로드 |
|---|---|---|---|
| 좋아요 | `like_posts` | `like_discussion_post(links, accountIds)` | `{links[], loginIds[]}` |
| 싫어요 | `dislike_posts` | `dislike_discussion_post(...)` | `{links[], loginIds[]}` |
| 조회수 | `boost_view` | `boost_view_count(links, repeats)` | `{links[], repeats}` |
| IP 변경 | `rotate_ip` | `rotate_ip()` (자기 PC) | `{}` |

> 좋아요/싫어요/조회수/IP변경은 **게시 큐를 안 타는 즉시 실행 IPC**다. 에이전트는 `enqueue_publish`가
> 아니라 해당 함수를 직접 부르고 결과를 서버로 회신한다(§6 결과 회신은 질문).

## 3. 게시 명령 — 닉네임 랜덤 (종토 댓글)

### 3-1. 위치·노출 조건
- **위치**: `ForumCommentConfig`에서 **계정 선택 밑 · [지금 게시] 버튼 위**에 체크박스.
- **노출 조건**: 선택한 대상 글의 **작성 댓글 수 ≥ 2**일 때만. **댓글 1개면 계정을 여러 개 골라도 숨김.** (데스크톱 게이트: forum + comment/both. Admin은 여기에 "댓글 수 ≥ 2" 추가.)
- 체크 시 그 밑에 **`계정명 : 닉네임 변경 가능횟수 n회`** 를 계정마다 표시.

### 3-2. 동작 (재사용)
2개 이상 댓글 + 링크 + 여러 계정 + 랜덤 → **각 계정이 그 링크에 자기 댓글들을, 계정 내 중복 없는 랜덤 닉으로 게시.
5회까지 바꾸고 이후엔 마지막(5번째) 닉으로 계속. 계정 수만큼 독립 반복** — 데스크톱과 100% 동일(엔진이 이미 처리).
→ Admin은 publish payload에 `commentNicknameRandom: true`만 실으면 됨.

### 3-3. ⚠ 없는 배선 (신규 필요)
1. **에이전트 하드코딩 해제**: `agent/mod.rs`가 모든 builder에서 `comment_nickname_random: false`로 박아둠(`:1102,1171,1367,…`) → payload 값을 반영하도록 변경.
2. **서버 PublishSpec + Admin payload**에 `commentNicknameRandom` 필드 추가.
3. **댓글 수(≥2 게이트용)**: Admin은 현재 **글의 댓글 개수를 모른다.** 인벤토리(`agent/mod.rs inventory_body:404`, 서버 `DeviceInventory`/`InvPost` `model.rs:78`)에 **글별 댓글 수를 추가 보고**해야 Admin이 게이트할 수 있다.
4. **잔여 횟수 표시**: 하위가 `forum_nickname_remaining`을 **계정별로 조회해 Admin에 반환**하는 경로 신규(질의 명령 or 인벤토리 확장). 데스크톱은 IPC 직접 호출이지만 Admin은 원격이라 에이전트 왕복 필요.

## 4. 게시 명령 — 게시 후 내용변경 (종토 글)

### 4-1. 위치·노출
- **노출**: **종목토론방일 때만** 체크박스(카페/블로그/클립/밴드엔 안 뜸 — 데스크톱과 동일).
- **위치**: `ForumConfig`에서 **종목 수와 계정 사이**.
- UI: 체크하면 **바꿀 제목 / 내용 / 지연(초)** 입력 — 데스크톱 내용변경 블록(`publish-modal.tsx:2312-2388`) 이식.

### 4-2. 동작 (재사용)
게시 성공 후 지연(초) 뒤 그 글을 새 제목/내용으로 edit. 성공/실패 토스트·알림·백트레이스까지 데스크톱 흐름 그대로(엔진 `spawn_forum_content_edit`가 처리).
→ Admin은 payload에 `contentChange{title,body,delaySec}`만 실으면 됨.

### 4-3. 없는 배선 (신규 필요)
1. **에이전트 하드코딩 해제**: `content_change: None`으로 박힌 곳(`agent/mod.rs:1103,1172,…`) → payload 반영.
2. **서버 PublishSpec + Admin payload**에 `contentChange` 필드 추가.
3. Admin `ForumConfig`에 체크박스+입력 UI 이식.

## 5. 신규로 만들 것(요약) vs 재사용

**재사용(있음, 안 만듦):** 좋아요/싫어요/조회수/IP변경 엔진, 닉네임 회전·5회한도·잔여횟수 엔진, 내용변경 엔진,
게시 큐, 데스크톱 UI 블록/모달, Admin 기기선택·계정필터·명령 파이프.

**신규(없음, 만듦):**
1. Admin **기타 명령 페이지**(웹) + 네비 1줄.
2. 에이전트 **새 명령 4종**(`like_posts`/`dislike_posts`/`boost_view`/`rotate_ip`) + 서버 발행 경로(generic `issue_command` 확장 또는 전용 엔드포인트).
3. publish payload/서버 PublishSpec에 **`commentNicknameRandom`·`contentChange`** 필드 + 에이전트 하드코딩 해제.
4. Admin **ForumCommentConfig에 닉네임 랜덤 체크박스**(≥2 게이트·잔여횟수 표시), **ForumConfig에 내용변경 체크박스**.
5. **인벤토리에 글별 댓글 수** 추가(≥2 게이트용).
6. **계정별 닉네임 잔여횟수** 원격 조회 경로.

## 6. 확정 결정 (2026-07-12, 사용자 확정)

1. **댓글 수(≥2 게이트) 출처**: ✅ **하위 인벤토리에 `commentCount` 필드 1개 추가** (에이전트가 `LibraryPost.comments.length` 실어 보냄). `InvPost`(`server/src/model.rs:49`)에 필드 추가. Admin이 종토 댓글 글을 선택하면 그 글의 댓글 수를 알게 됨 → **N≥2일 때만** 닉네임 랜덤 체크박스 노출, N=1이면 계정 여러 개여도 숨김.
2. **닉네임 잔여횟수 조회**: ✅ **(a) 실시간 조회**. 체크박스 켤 때 하위 에이전트가 계정별 `forum_nickname_remaining` 호출→서버→Admin 왕복. 표시 전까지 "확인 중…". (근거: 프로필 form GET은 로그인이 아니라 봇탐지와 무관하고, 온디맨드 1회라 주기 GET(b)보다 오히려 트래픽이 적다. 데스크톱도 이미 (a).)
3. **결과 표시**: ✅ **Admin 결과 보고(게시 결과) + 통신 로그 둘 다**. 에이전트가 `post-report`(`routes.rs:1123·1164`)로 회신 → 결과 보고에, `agent_log`(`routes.rs:1238`) 포워딩 → 통신 로그에. 좋아요/싫어요/조회수/IP는 게시가 아니므로 게시 결과 목록에 **종류 태그(게시/좋아요/싫어요/조회수/IP)**를 붙여 통합 표시. (하위 데스크톱은 이미 로컬 모달/토스트로 표시 — 그대로 둠.)
4. **좋아요/싫어요 계정 목록**: ✅ 그 하위의 **종토(forum) 로그인 성공(active) 계정 전부** 노출 (게시명령 `filterAccountsByTarget` forum과 동일 규칙).
5. **IP 변경 대상에 폰/ADB 없을 때**: ✅ `rotate_ip` 실패 시 앱이 죽지 않고 **"IP 변경 실패" 토스트 + 로그**로 알림.
