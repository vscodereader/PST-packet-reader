# Admin 게시명령 — 댓글/글+댓글 확장 설계서

- 작성일: 2026-07-06
- 대상 PR: #324 (`docs/admin-remote-control-design`)
- 요구 문서: `Design_Doc/Admin 댓글 기능 추가 설계 요구.txt`
- 원칙: **기존 pstmacro 코드 재사용**(댓글 UI·플랜 빌드·엔진 다 있음), 없는 것만 신규, 무관 코드 무손상.

## 1. 요구 정리
게시명령에서 하위를 고르면 지금은 글/댓글/글+댓글이 다 섞여 나온다. 이를 **글 종류별로** 분리한다.
1. 하위 선택 후 **"글 종류를 고르세요"** 목록 → **글 / 댓글 / 글+댓글**. 고른 종류의 글만 목록에 뜬다(안 섞임).
2. **글**: 기존 종토 흐름(카테고리/시장/종목수 → 계정 → 지금/예약 게시) 그대로.
3. **글+댓글**: 글과 동일하되 글 게시 후 그 글에 저장된 댓글까지 함께 게시.
4. **댓글**: 대상으로 최신글/인기글/특정게시글 중 선택.

## 2. ★코드 실측 결과 — 종토 최신글/인기글 댓글은 엔진에 없음
요구는 "최신글/인기글도 코드에 있으니 재사용"이었으나, **정독 결과 종목토론방(forum)의 최신글-N/인기글-N 댓글은 엔진에 구현돼 있지 않다.**
- `run_forum_publish`(discussion_batch.rs)는 **종목당 1개만** 처리, count 개념 없음. `ForumTarget`엔 count/mode 필드 없음.
- "대상마다 N개"의 count는 **카페·블로그·클립·밴드에만**(`CommentTargetSpec.count`) 연결됨. 종토엔 안 감.
- 종토 URL을 비우면 목록 API(`/api/community/discussion/posts/by-item`)를 부르지만 **랜덤 1개만** 고름(`select_random_discussion_post`). "최신 N개에 각각 1개"는 없음.
- **지원됨**: 종토 댓글 = 특정게시글(URL, `ForumTarget.comment_url`) ✅, 랜덤 1개 ✅.

→ **사용자 확정(2026-07-06): "종목토론방일 땐 댓글을 선택하면 특정 게시글만 나오게."** 최신글/인기글은 종토 UI에서 제외. (최신/인기-N은 카페 등 다른 플랫폼 활성화 시 그 엔진으로.)

## 3. 확정 설계 (종목토론방 기준)
하위 선택 → **글 종류**(글/댓글/글+댓글) → 그 종류 글만 목록.
- **글**(`mode=post`): 카테고리/시장/종목수 → 계정 → 지금/예약(+나눠서). 기존 그대로.
- **글+댓글**(`mode=both`): 위와 동일 UI. 엔진 `ModeValue::Both`로 글 게시 후 그 글에 저장 댓글까지(엔진 기존 동작). 에이전트가 글의 `comments`를 plan에 실어줌.
- **댓글**(`mode=comment`): **특정 게시글 URL 여러 개 입력 + "링크 추가"** → 계정 → 지금/예약(나눠서 없음). 각 URL의 글에 저장 댓글을 단다(엔진 `comment_url` 경로). 계정마다 같은 URL들에 단다.

## 4. 재사용 / 신규 지도
| 부분 | 재사용? | 위치 |
|---|---|---|
| 글 종류(글/댓글/글+댓글) 개념 | 재사용 | `ModeValue`(posts.rs), `LibraryPost.kind` |
| 댓글 대상(최신/인기/특정) · 링크 입력 · 링크추가 · "대상마다 N개" UI | 재사용(로컬) | `writer-modal.tsx`(CommentComposer) |
| 종토 댓글 — 특정게시글(URL) 엔진 | 재사용 | `ForumTarget.comment_url` → `run_naver_discussion_macro` |
| 글+댓글 엔진(글 후 댓글) | 재사용 | `ModeValue::Both` → `run_naver_post_with_comment_macro` |
| 지금/예약 게시 | 재사용 | `api.publish.send`/`api.scheduled.create` |
| **글 종류 필터용 인벤토리 kind** | 신규 | 아래 §5-1 |
| **게시명령에 mode·comment_urls 전달** | 신규 배선 | 아래 §5-2 |
| **Admin 댓글 화면(특정게시글)** | 신규(로컬 UX 이식) | `ForumCommentConfig`(publish-command.tsx) |

## 5. 구현
### 5-1. 인벤토리에 글 종류(kind) 추가 (글 종류 필터용)
기존 인벤토리 글은 `{id,title}`뿐이라 종류 필터 불가 → `kind` 추가.
- 에이전트 `inventory_body`: 글마다 `kind`("post"|"comment"|"both") 포함(`agent/mod.rs`, `mode_to_str`).
- 서버 `InvPost`에 `kind` 추가(`server/model.rs`, `#[serde(default)]` 하위호환).
- Admin `InvPostDto.kind?` + `postsForKind`로 선택 종류 글만 목록.

### 5-2. 게시명령에 게시 종류·댓글 URL 전달
- 서버 `PublishSpec`에 `mode: String`·`comment_urls: Vec<String>` 추가 + `dispatch_publish` payload에 `mode`·`commentUrls`(`server/scheduled.rs`).
- 에이전트 `PublishCmd`에 `mode`·`comment_urls` 추가. `load_post`가 `comments`도 로드. `build_publish_items`가 mode 분기(`agent/mod.rs`):
  - `comment`: 계정 × URL마다 `ForumTarget{comment_url}` (kind=Comment, plan.comments=글 댓글).
  - `post`/`both`: 계정 × 종목(kind=Post/Both, both면 plan.comments 실음).
- Admin `api.publish.send`/`scheduled.create`에 `mode`·`commentUrls?`.

### 5-3. Admin UI(`publish-command.tsx`)
- ① 하위 카드에 **글 종류 Select**("글 종류를 고르세요") → 그 종류 글만 아래 글 Select에.
- ② DeviceBlock가 kind로 분기: 글/글+댓글 → `ForumConfig`(mode 전달), 댓글 → **`ForumCommentConfig`**(URL 입력 3칸 기본 + 링크 추가 + 계정 + 지금/예약).
