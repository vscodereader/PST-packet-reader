# 04. 결과 보고 화면 (로그인 결과 + 게시 결과)

- 설계서 근거: `설계.md` §10-4(로그인 결과, 4분류+누적), §10-4-2(게시 결과, 백트레이스·게시내용·링크)
- 코드: `src/admin/features/result-report/result-report.tsx`
- 상태: UI만 (더미 — §10-4 예시 그대로)
- 상단 **[로그인 결과] / [게시 결과]** 토글로 전환.

## 게시 결과 (§10-4-2) — 데스크톱 앱 알림과 동일 모델

device별 게시 배치 카드. 각 대상(어디에 게시했는지) 한 줄씩:

- **성공**: ✓ + 플랫폼 + 대상 + 계정 → **[게시 내용]** 펼치면 제목/본문/댓글 + **글 URL 링크**(클릭 시 열림).
- **실패**: ✗ + 친절한 사유 → **[자세히 보기]** 펼치면 **어두운 콘솔 박스에 백트레이스**(원인 체인 + `at 함수(파일:줄)` + 스택). `util.rs`의 `transport_error_message!` 형식 그대로.
- 데스크톱 앱 `notifications.tsx`의 `SubLog`·`BatchItem`·`PostedContent` 모델을 그대로 재사용.
- **컴퓨터당 8곳까지 보이고 그 이상은 세로 스크롤(드래그바)**.
- **성공/실패 배지 클릭 = 필터**: `성공 N` 누르면 성공만, `실패 N` 누르면 X 표시된 실패만(다시 누르면 전체). 카드마다 독립.

## (로그인 결과) 구성 — device별 카드

각 하위(device)마다 카드 1개:

- **헤더**: device 이름 + 이번 배치 4분류 배지(성공/보류/대기초과/실패)
- **이번 배치 상세**:
  - **성공**: 개수만(ID/PW 안 적음 — 로그인돼 하위에 남음)
  - **보류**: ID · PW(마스킹) · 보류사유(캡차/전화번호 등)
  - **대기초과**: ID · PW (사유 없음)
  - **실패**: ID · PW · 실패사유 — **보고 후 자동 삭제됨**
- **누적**: `총 받은 계정 X · 성공 a / 보류 b / 대기초과 c / 실패 d` (배치마다 갱신)

## 표시 규칙 (마스킹·정렬·스크롤) — §10-4-1

- **마스킹**: ID·PW 모두 **앞 2글자만 노출**, 나머지 `•`. 예: `stock_id041`→`st•••••••••`, `ik7!naver22`→`ik•••••••••`.
- **정렬**: ID·PW 열 고정폭(150·120)으로 분류 섹션 간 세로 정렬. (보류=3열, 대기초과=2열이어도 ID·PW 위치 동일.)
- **누적 스크롤**: 결과가 쌓이므로 상세 목록은 최대 높이(약 260px)까지만 보여주고 **나머지는 세로 스크롤(드래그바)**. 누적 합계는 카드 하단 고정.

## 색상

성공=초록 / 보류=노랑 / 대기초과=회색 / 실패=빨강.
