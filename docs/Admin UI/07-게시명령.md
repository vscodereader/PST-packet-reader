## 0. 대원칙 (반드시 지킬 것)

1. **하위 컴퓨터당 1묶음 — 절대 섞지 않는다.** 하위 3대를 고르면 각 대의 (선택한 글 · 종목 카테고리 · 성공 계정)이 **완전히 분리된 3개의 독립 게시 구성**이 된다. 한 대의 글/계정/종목이 다른 대로 새지 않는다.
2. **게시 로직은 100% 기존 엔진 재사용.** 종토·카페·블로그·밴드에 글을 올리는 코드는 이미 있으므로(§5·§6), Admin은 **"어느 하위가 · 무슨 글을 · 어디에 · 어떤 계정으로" 만 골라 명령(`publish_posts`)으로 내려보내고**, 실제 게시는 하위(기존 pstmacro 큐)가 자기 IP로 수행한다.
3. **글·쿠키·게시큐는 하위 로컬.** Admin은 글 본문을 저장하지 않는다. 명령엔 **글 식별자(`postId`)만** 싣고, 하위가 자기 `글 관리`의 그 글을 꺼내 게시한다(§7 데이터 소유 원칙 그대로).

## 2. ① 상단 — 하위 COM 카드 + 글 선택

### 표시 대상

- **계정을 분배받고 로그인까지 마친 online 하위만** 카드로 뜬다.
  - 판정: §4 상태머신 `온라인/준비` **그리고** 그 하위의 누적 로그인 성공(`Active`) 계정 ≥ 1 (§10-4 누적 `success`).
  - `IP변경중`·`재연결`·`오프라인`, 또는 아직 로그인 성공 계정이 0인 하위는 제외.
  - 데이터: 계정 분배 화면과 같은 `api.devices.list()`(online 필터) + 신규 "성공 계정 있음" 플래그(아래 §4 데이터흐름).

### 배치 (4열 그리드)

- **한 줄에 4장(4×N)**. 8대면 위 4 + 아래 4. 카드 = **흰색**(`Paper withBorder`), 안에 **컴퓨터 아이콘(`IconDeviceDesktop`) + 하위 이름**.
- 계정 분배 화면의 하위 카드 스타일 재사용(`account-distribute.tsx:443-472`의 `Paper`/`ThemeIcon`/이름), 세로 리스트를 **4열 그리드(`SimpleGrid cols={4}`)** 로 바꾼 것.

### 카드 밖 아래 = 글 셀렉트박스

- 카드마다 **바로 아래에 셀렉트박스** 1개, 기본 문구 **"글을 선택하세요"**, **처음엔 비활성(disabled)**.
- **카드를 선택(클릭)** 하면:
  - 카드 **테두리가 파란색**으로 바뀐다(선택 표시, `account-distribute.tsx`의 파랑 강조 패턴).
  - 그 카드의 **글 셀렉트박스가 활성화**된다.
- 셀렉트박스를 누르면 **그 하위의 `글 관리`에 저장된 글 목록**이 뜬다.
  - 하위 3개 글을 썼으면 3개가 보인다.
  - **라벨은 최대 6자까지만 보이고 나머지는 `…`** 로 말줄임(`maxWidth` + `text-overflow: ellipsis`, 또는 `title.slice(0,6)+"…"`).
  - **글 1개 선택 = 그 하위가 로그인된 계정들로 그 글을 게시** 한다는 뜻(대상·종목·계정은 ②③에서 확정).

## 3. ② 게시 대상 버튼 4개

- **[종목토론방] [네이버카페] [네이버블로그] [네이버밴드]** — 누른 버튼의 플랫폼으로 게시한다.
- 하나를 누르면 그 대상용 상세 구성(③)이 아래에 뜬다. **이번 설계는 [종목토론방]만 확정**(카페·블로그·밴드는 §7).
- 각 버튼은 **기존 게시 엔진의 대상별 경로**로 바로 연결된다(하위에서 실행):

| 대상 | 하위 최상위 실행 함수 | 대상 파라미터(무엇이 필요한가) |
| --- | --- | --- |
| 종토 | `run_forum_targets` → `run_forum_publish` (`queue_runner.rs:1840`, `discussion_batch.rs:212`) | `ForumTarget{account_id,name,code}` — **종목 code 목록** (`queue.rs:90`) |
| 카페 | `execute_item`→`run_post_jobs_with_progress` (`queue_runner.rs:620`, `naver_cafe/orchestrator.rs:534`) | `NaverTarget{account_id,cafe,menu_id,board_type,…}` — **카페+게시판** (`queue.rs:70`) |
| 블로그 | `run_blog_targets` → `create_blog_comment_for_account` (`queue_runner.rs:2174`, `naver_blog/mod.rs:22`) | `BlogTarget{account_id,blog_id,log_no|count,category_no?}` — **댓글 전용** (`queue.rs:128`) |
| 밴드 | `run_band_targets` → `band_publish` (`queue_runner.rs:2064`, `band_post/mod.rs:92`) | `BandTarget{account_id,link,…}` — **밴드 링크** (`queue.rs:107`) |

> 즉 Admin은 대상별로 위 target 구조를 채워 `publish_posts` 명령에 실으면 되고, **하위는 기존 `PublishPlan`/큐 경로를 그대로 태운다**(§5).

## 4. ③ (종토) 하위별 종목·계정 구성 — **대원칙 0-1의 핵심**

[종목토론방]을 누르면, **①에서 선택한 하위마다 독립 패널이 하나씩** 뜬다. 하위 3대면 패널 3개. 각 패널은 그 하위의 (선택한 글 · 종목 · 성공 계정)만 다룬다 — **서로 절대 섞이지 않는다.**

### 4-1. 카테고리 6버튼

- **토론 · 거래대금 · 인기종목 · 상승 · 하락 · 거래량** — 6개 버튼.
- **기존 종목선택 UI와 1:1 동일**: `stock-crawl-modal.tsx:27-34`의 `CATEGORIES`(`discussion`/`tradingValue`/`popular`/`rising`/`falling`/`volume`)와 완전히 같다. → 카테고리 정의·라벨 **재사용**.

### 4-2. 시장 3버튼

- 6버튼 중 **하나라도 누르면** 그 아래에 **전체 · 코스피 · 코스닥** 3버튼이 뜬다.
- 기존 `MARKETS`(`stock-crawl-modal.tsx:37-41`, `all`/`kospi`/`kosdaq`)와 동일 → **재사용**.
- (기존 규칙 그대로) **토론 카테고리는 시장 구분이 없어 `전체` 고정**(`stock-crawl-modal.tsx:59-60`).

### 4-3. 종목 미리보기 (요구: "기존 종목선택 UI에서 나오는 종목들이 나와야 한다")

- 카테고리+시장을 고르면 **그 조합의 실제 종목 목록**을 화면에 보여준다(불꽃🔥 아이콘 포함).
- 데이터 원천 = 기존과 **동일**: `list_forum_stocks(category, exchange, market, page)`(`forum_stocks/mod.rs:163`, IPC `src/shared/ipc/index.ts:227`). Naver `m.stock.naver.com` front-api, 카테고리→정렬 매핑 `client.rs:17-26`(거래대금→`priceTop`, 거래량→`quantTop`, 상승→`up`, 하락→`down`, 인기→`searchTop`, 토론→랭킹).
- 불꽃🔥 = `isHotDiscussion`(`ForumStock`, `mod.rs:86` / `bindings/ForumStock.ts`), 아이콘 렌더 `stock-crawl-modal.tsx:269-271`.
- **Admin(웹)에서 이 목록을 어떻게 얻나 = 사수 결정(§6 결정 A)**. 권장안: 선택 로직을 **하위(Rust)에서** 돌리고(아래 4-4), Admin 미리보기는 **서버가 같은 front-api를 프록시**해 보여준다(로그인 불필요·공개 랭킹).

### 4-4. 종목 수 N 입력 + 선택 알고리즘 (**신규 로직**)

- 시장 버튼 옆에 **숫자 입력 텍스트필드**(`NumberInput`). 입력한 N만큼 종목을 자동 선택한다.
- ⚠️ **현재 코드에 없는 신규 로직.** 기존 종목선택은 **수동 체크박스만** 있고(상위 N 선택·불꽃 우선정렬 모두 없음, `stock-crawl-modal.tsx:133-140`). 아래 규칙을 신규 구현한다.

**선택 규칙 (요구 그대로)**

전제: 대상 후보 = (선택한 카테고리+시장의 종목 목록) − (제외 대상, 4-5). 목록 순서는 Naver 정렬 순서 그대로.

1. **불꽃🔥 종목을 목록 순서대로 먼저 채운다.**
2. 불꽃으로 N을 못 채우면, **나머지는 불꽃 없는 종목 중 맨 위에서부터 순차** 로 채운다.
   - 예: N=20, 불꽃 15개 → 불꽃 15개 전부 + 비불꽃 위에서 5개 = 20.
3. **불꽃 개수 ≥ N** 이면, 불꽃 종목 중 **목록 순서 상위 N개**만.
   - 예: N=20, 불꽃 30개 → 불꽃 위에서 20개(나머지 10개 미선택).
4. **N > 실제 가용 종목수 M** 이면, **가용 M개 전부 선택** + 아래 오류 문구 표시.
   - 문구: **`선택 N, 실종목 M개, 선택불가 N−M개`** (요구 예: `선택 100, 실종목 n개, 선택불가 100-n개`).

**구현 위치(권장)**: 순수 함수로 하위 Rust `forum_stocks`에 신규 추가(이름·시장 필터 이웃). 목록을 다 받아(`hasNext` 끝까지) 위 규칙으로 N개 code를 뽑는다. 단위테스트로 4가지 케이스(정상/불꽃부족/불꽃초과/N초과) 고정.

### 4-5. 제외 규칙 — 삼전·하이닉스 (**신규 로직**)

- **이름에 `삼전`·`삼성전자`·`하이닉스`가 들어간 종목은 불꽃 유무와 무관하게 제외.** (요구: "삼전과 하이닉스 라는 말이 들어간 종목은 불꽃표시가 있든 없든 선택하지 말 것.")
- 현재 이런 이름 제외는 **없음**(확인 완료). **유일한 기존 제외 = ETN·레버리지**: `is_hidden_stock`(`forum_stocks/mod.rs:111-113`) → `drop_hidden_stocks`(`:118-120`)가 모든 경로에 적용.
- → **`is_hidden_stock`에 이름 토큰 `삼전`/`삼성전자`/`하이닉스`를 추가**하거나, 게시 명령 전용 별도 제외 함수를 같은 패턴으로 신설(사수 결정 §6-B). 제외는 4-4 선택 **이전**에 적용(선택 후보에서 아예 빠짐).
  - (검토 필요) `삼성전자` 포함 시 `삼성전자우`(우선주)도 함께 제외됨 — 의도로 보임. 정확한 토큰은 사수 확인.

### 4-6. 계정 선택 — "성공한 계정만", 하위별로 분리

- 종목 선택이 끝나면 그 아래 **셀렉트박스**, 문구 **"계정을 선택하세요"**.
- 누르면 **그 하위 컴퓨터의 로그인 성공(`Active`) 계정만** 뜬다. (보류·대기초과·실패 계정은 안 뜸.)
  - `Active` = 로그인 성공(`auth/outcome.rs:101` `Ok→Active`, `AccountStatus`(`accounts.rs:40`)). 데스크톱 게시 화면도 `isPostable` 계정만 노출(`publish-modal.tsx:152,1267`) — 같은 규칙.
- **여러 하위를 골라도 계정이 섞이지 않는다**: 이 계정 셀렉트는 **그 패널(그 하위)의 성공 계정만**. 다른 하위의 계정은 절대 안 섞임(대원칙 0-1).
- 표시 마스킹: §10-4-1대로 **ID 앞 2글자 + `•`**(예: `stock_id041`→`st•••••••••`).

| 성공 계정만 노출 | **재사용(규칙)** | `Active`(`outcome.rs:101`), `isPostable`(`publish-modal.tsx:152`) |
| ID 마스킹(앞 2글자) | **재사용** | §10-4-1 |

## 5. ④ [게시하기] — 명령 발행 & 기존 큐 재사용

계정까지 고르면 맨 아래 **[게시하기]** 버튼. 누르면 **선택한 하위마다 독립 명령 1개씩** 발행한다(대원칙 0-1: 대별로 분리, 섞임 없음).

### 명령 형태 (신규 command type `publish_posts`)

기존 명령(`import_then_login_all`·`distribute_accounts`, §10-1·§10-3)에 **게시 명령을 추가**한다. §3대로 **그 하위가 연 SSE 파이프**로 내려간다.

```
POST /devices/{deviceId}/commands
{
  commandId,
  type: "publish_posts",
  postId,                 // ①에서 고른 글(그 하위 로컬 LibraryPost.id) — 본문은 하위가 보유
  target: "forum",        // ② 대상. 이번 설계는 forum(종토)만
  forum: {                // ③ 종토 구성 (대상별로 이 자리만 달라짐)
    category, market,     // 카테고리+시장 (미리보기·재현용)
    count: N,             // 종목 수 (하위가 4-4 규칙으로 선택) — 또는 resolvedCodes(사수 §6-A)
    excludeNames: ["삼전","삼성전자","하이닉스"]
  },
  accounts: [loginId, …]  // ③ 그 하위의 성공 계정 중 고른 것만
}
```

### 하위(에이전트) 실행 — **전부 기존 부품**

```
[하위] publish_posts 수신
  → postId로 로컬 글(LibraryPost) 로드 (posts.rs / list_posts)
  → target=forum: 4-4 규칙으로 종목 N개 code 선택(신규 순수함수) → 삼전/하이닉스·ETN 제외
  → 계정×종목code로 ForumTarget 목록 구성 → PublishPlan.forum 채움
     (프론트 buildPlanFromJobs(publish-modal.tsx:1614)와 동일 조립, 하위 큐용으로 재사용)
  → add_queue_now(QueueNowItem{plan}) (queue.rs:496) → NowQueueRunner.execute_item(queue_runner.rs:456)
  → run_forum_targets → run_forum_publish (기존 게시 엔진 그대로)
  → 결과 LogBatch 생성(build_log_batch) → Admin에 게시 결과 보고(§10-4-2)
```

- **토큰 치환**(`#{종목명}`·`#{링크}`)도 기존 `template_tokens.rs`가 그대로 처리 → 종목마다 본문 자동 치환.
- **게시 결과**는 §10-4-2 그대로 결과 보고 화면에 나온다(어디에·무엇을·성공/실패·백트레이스). 신규 모델 없음.

### 재사용 / 신규 요약 (게시하기)

| 부품 | 처리 | 근거 |
| --- | --- | --- |
| 명령 발행 경로(POST→SSE) | **재사용** | §3, `POST /devices/{id}/commands`(§10) |
| `publish_posts` 명령 타입 | **신규(작음)** | 파라미터만 신설, 라우팅은 기존 |
| Plan 조립(계정×종목→ForumTarget) | **재사용** | `buildPlanFromJobs` 로직(`publish-modal.tsx:1614`), `ForumTarget`(`queue.rs:90`) |
| 큐 실행 | **재사용** | `add_queue_now`(`queue.rs:496`)→`execute_item`(`queue_runner.rs:456`)→`run_forum_targets` |
| 토큰 치환 | **재사용** | `template_tokens.rs` |
| 게시 결과 보고·표시 | **재사용** | §10-4-2, `result-report.tsx`·`mapping.ts` |

## 6. 사수 결정 요청 (구현 전 확정 필요)

- **B. 삼전/하이닉스 제외 토큰**: 정확히 어떤 문자열을 막을지 — `삼전`·`삼성전자`·`하이닉스`(+`SK하이닉스`)? `삼성전자우`(우선주)도 제외 맞는지?
