# 13. 네이버 밴드 — 계정 분배 + 게시 명령 (Admin)

> 카페(10)·블로그(11) 문서의 형제. 배선 구현 완료(설계+구현).
>
> **대원칙:** 밴드 기능(band.us 로그인·글 게시·댓글·밴드명 조회)은 **이미 하위(com pstmacro)에
> 전부 구현돼 있습니다.** 그러니 **기존 밴드 엔진과 기존 데스크톱 UI를 한 줄도 고치지 않고 그대로
> 재사용**하고, Admin은 "이 밴드에 이 계정으로 글/댓글을 올려라"는 **명령만** 내려보냅니다.
> **없는 배선만 새로 만들고, 있는 것은 절대 새로 만들지 않습니다.** 아래 **§1 재사용 지점**에
> "무엇을·어디서(`file:line`)·어떻게" 재사용하는지 전부 적어 두었습니다.

## 0. 한눈에

밴드는 **카페와 성격이 비슷**합니다 — **글/댓글/글+댓글을 모두** 지원합니다(블로그·클립처럼 댓글
전용이 아님). 단 로그인이 다릅니다: 밴드는 네이버가 아니라 **band.us 별도 로그인**이고, **분배 때
로그인**해 밴드 쿠키를 확보합니다(종토·블로그와 같은 "분배 시 로그인" 흐름 — 카페의 "게시 순간
로그인"과 다름).

게시 종류별 동작(엔진에 이미 구현 — `queue.rs:101` `BandTarget` 머리말):

| 글 종류 | 엔진 | 동작 |
|---|---|---|
| **글 / 글+댓글** | `band_publish`(`band_post/mod.rs:92`) | 밴드에 **새 글** 게시(글+댓글이면 그 글에 댓글까지) |
| **댓글(최신/인기)** | `band_comment`(`band_post/mod.rs:209`, `BandFeedSort::{Latest,Popular}`) | 밴드의 **최신/인기 상위 N개** 글에 댓글 |
| **댓글(특정 글 URL)** | `band_comment_on_post`(`band_post/mod.rs:355`) | **특정 글 URL 1건**에 직접 댓글("카페·종토 url 댓글의 밴드판") |

> ✅ **밴드 댓글은 최신·인기·특정 글 URL 3가지 모두 지원합니다**(종토·카페와 동일). 실행 분기는
> `queue_runner.rs:2216`(url이면 `band_comment_on_post`, 아니면 최신/인기 `band_comment`). 대상 모드/
> 개수는 카페처럼 글(댓글 템플릿)의 `commentTarget`/`commentCount`에 **동결**된 값을 그대로 씁니다.
>
> 📌 참고: `queue.rs:113` `BandTarget` 머리말 주석은 "url 댓글 미지원"으로 **낡아 있습니다**(실제
> 러너는 `band_comment_on_post`로 url을 처리). 레포 주석 오탈 — 이 설계 작업 범위 밖이라 안 고쳤습니다.

> ⚠️ **글쓰기 한계(코드로 못 뚫음)**: **리더 승인제** 밴드는 `band_publish`의 `create_post`가
> `result_code=1003`("리더 승인 후 등록")을 반환해 **글이 즉시 안 올라가고 승인 대기**가 됩니다
> (`queue_runner.rs:2194` 주석). 밴드 정책이라 우회 불가 — 승인제 밴드에서는 글쓰기가 바로 반영되지
> 않습니다(댓글은 영향 없음).

Admin은 데스크톱 밴드 카드와 **동일한 UX**(밴드 링크 입력 → 목록 → 선택 칩)를 이식하고, `지금 게시`/
`예약 게시`를 누르면 그 명령이 하위로 내려가 하위 큐 러너가 밴드 쿠키로 게시/댓글을 수행합니다.

## 2. 계정 분배 — 플랫폼 열 + 밴드 = band.us 로그인해서 등록

- **UI**(`account-distribute.tsx`): 카페·블로그와 **동일한 플랫폼 Select**에 `밴드`(`band`)를 노출
  (이미 `PlatformId::Band`·`platform_from_str("band")` 존재). — **새 옵션 추가 불필요.**
- **명령 경로**: `import`에 `platform:"band"` → 서버 `StagedAccount.platform` → 분배 payload
  `{loginId, pw, platform:"band"}` → 하위 `AccountIn.platform`.
- **하위 등록/로그인 분기**(`agent/mod.rs distribute_accounts`:487): 밴드는 **카페가 아님**
  (`is_cafe_platform("band")==false`)이라 **분배 직후 자동 로그인**(`enqueue_login`)합니다(종토·블로그와 동일).

> ⚠️ **여기 하나가 "없는 배선"입니다(밴드만의 유일한 실질 작업).** 현재 `enqueue_login`은 모든 로그인
> 대상을 `platform: PlatformId::Naver`로 하드코딩합니다(`agent/mod.rs:1244`). 클립/블로그/종토는
> 네이버 로그인이라 이대로 맞지만, **밴드는 band.us 로그인이라 `PlatformId::Band`가 필요**합니다
> (러너가 :1814·:2534에서 `Band`일 때만 `process_band_account`로 분기하기 때문). 따라서
> `enqueue_login`(또는 `distribute_accounts`의 로그인 적재부)을 **계정 플랫폼에 따라 `platform`을
> 정하도록** 바꿔야 합니다(밴드=`Band`, 그 외=`Naver`). **엔진은 무손상 — 로그인 대상 조립만 고칩니다.**

## 3. 게시 명령 — 밴드 링크(글/댓글/글+댓글)

- **UI**(`publish-command.tsx`): 현재 밴드는 `TARGETS`에서 `{ key:"band", label:"네이버밴드", soon:true }`
  (:69)로 **버튼만 있고 비활성**입니다. 작업 = **`soon:false`로 열고 `BandConfig` 렌더**(카페 `CafeConfig`:1235 형제).
  - `밴드 링크` 입력 + `추가` → **`bandNoFromLink` 미러(순수)** 로 파싱해 목록(select)에 누적. 카페가
    게시판 링크(menu)와 특정 글 링크(article)를 함께 받듯, 밴드도 **밴드 홈 링크**(글/최신/인기용)와
    **특정 글 URL**(url 댓글용, band_no+post_no)을 함께 받습니다 — url 댓글은 `t.link`에 그 글 URL을 실어야 함.
  - Select → 고른 밴드가 아래 **동그라미 칩**(제거 X 포함). 여러 링크 → 여러 밴드 다중 선택.
    **데스크톱 밴드 카드(:695 드롭다운·:711 칩)와 동일.**
  - **글 종류 3가지 공통**(카페와 동일): 글/글+댓글=밴드에 새 글, 댓글=**최신/인기/특정 글 URL**. 댓글
    대상 모드(latest/popular/url)/개수는 글(`commentTarget`/`commentCount`)에 **동결**된 값 사용(카페와 동일 — 여기서 안 고름).
  - 계정 = **이 하위의 밴드(`band`) 계정 중 로그인 성공(active)**.
- **명령 경로**: `publish.send`/`scheduled.create`에 `target:"band"` + `bandTargets:[{bandNo, link}]`
  추가 → 서버 `PublishSpec.target`/`band_targets`(신규, `PublishCafeBoard`:66 형제) → payload → 하위 `PublishCmd`.

> ℹ️ **밴드명 실시간 조회는 하지 않습니다(안 함).** 데스크톱은 저장 시 밴드명을 조회하지만
> (`publish-modal.tsx:684` `bandResolving`) 그건 **band.us 세션이 있는 하위**라서 가능합니다. Admin
> 웹엔 밴드 쿠키가 없으므로, 카페가 게시판명을 게시 시점 백엔드가 해석하듯 **Admin은 `band_no`만
> 파싱해 라벨(`밴드 {bandNo}`)로 쓰고, 실제 게시는 하위가 밴드 쿠키로 수행**합니다(band_publish가
> 링크에서 band_no만 뽑으므로 기능상 충분). — 라벨 표기 차이일 뿐, 새 조회 API 안 만듭니다.

## 4. 밴드 계정 노출

- Admin `accountsFor`(`publish-command.tsx:288`)에 **밴드 분기** 추가: `target==="band"`이면 인벤토리의
  **platform==band 계정 중 active**만(밴드는 분배 시 로그인하므로 로그인 성공만 게시 가능 — 종토·블로그와
  동일 규칙이고, **카페의 "로그인 무관 전부"와는 다릅니다**).
- 인벤토리 보고는 기존 `accountRows`(`agent/mod.rs:299`) 그대로 재사용 — 신규 필드 0.

## 5. 구현 체크리스트 (없는 배선만 신규 — ADD ONLY · 참고용, 이번 코멘트는 설계만)

**하위(에이전트) — 밴드만의 핵심 2건**
1. **로그인 플랫폼 분기(§2)**: `enqueue_login`(`agent/mod.rs:1236`)이 밴드 계정은 `LoginTarget.platform=Band`, 그 외는 `Naver`가 되도록 수정. (밴드의 유일한 엔진-외 실질 변경.)
2. `PublishCmd`(:124)에 `band_targets: Vec<BandTargetIn>`(`CafeBoardIn`:154 형제) 추가 + dispatch 분기(:699)에 `else if p.target == "band"` → `build_band_publish_items`(`build_cafe_publish_items`:902 형제): 계정×밴드로 `plan.band` 조립. 글/글+댓글=`comment_target None`, 댓글=`CommentTargetSpec{mode: 글의 commentTarget(latest/popular/url 그대로), count: 글의 commentCount}`(url 모드는 `BandTarget.link`에 특정 글 URL을 실음 — 러너가 `band_comment_on_post`로 처리).

**프론트(Admin)**
3. `publish-command.tsx`: band 타깃 `soon:false`(:69) + `BandConfig`(카페 `CafeConfig` 복제). `accountsFor`에 `target==="band"` → platform==band·active. `bandNoFromLink` 미러(순수).
4. `api.ts` `publish.send`/`scheduled.create`에 `bandTargets` 타입 추가(`cafeBoards`:391 미러).

**서버(server/)**
5. `scheduled.rs` `PublishSpec`에 `band_targets: Vec<PublishBandTarget>`(신규, `PublishCafeBoard`:66 형제) + `dispatch_publish` payload에 `bandTargets`(:154 `cafe_boards_json` 형제). (+ 테스트 `sched()` 리터럴에 `band_targets: vec![]` 추가.)

**엔진/실행 — 신규 0**: `run_band_targets`(:2163)가 `plan.band`를 그대로 처리(글=band_publish, 댓글=band_comment 최신/인기 N). `process_band_account`(로그인)·결과·백트레이스·통신로그는 기존 배선 자동 처리.

## 6. 범위 · 비범위

- **이번 범위**: 밴드 **글/댓글/글+댓글**을 Admin 명령으로. UI는 카페와 동일한 링크→목록→칩 UX.
  계정 취급은 종토·블로그와 동일(분배 시 로그인, active만 게시).
- **밴드는 5가지 모두 가능**: 글쓰기 · 글+댓글 · 댓글(최신 · 인기 · 특정 글 URL). 엔진에 전부 있음.
- **한계·비범위**:
  - ⚠️ **리더 승인제 밴드 글쓰기** — `result_code=1003`으로 즉시 반영 안 됨(승인 대기). 밴드 정책, 코드로 우회 불가(§0 주의). "못 만드는 것"이 아니라 밴드 자체 한계.
  - **밴드명 실시간 조회(Admin)** — band 세션 없어 미수행. `band_no` 라벨 + 게시 시점 하위 해석(§3 주의).
  - **밴드/카페/블로그/클립 엔진 수정** — 없음. 유일한 엔진-외 변경은 **로그인 대상 platform 분기(§2·§5-1)**.
- **실기기/실서버 검증은 사수/사용자 몫**(이 환경엔 폰·band.us 로그인 불가).
