# 18. 게시명령 종토 — 종목 자동/수동 선택 분기

- 근거: 사용자 요청(2026-07-20). 종토 게시 시 종목을 **자동(불꽃 우선 N개)** 대신 **직접 고르고**
  싶다는 요구. 기존 자동선택은 그대로 두고, **수동선택 분기를 추가**한다.
- 범위: **종목토론방(forum)의 글·글+댓글(post/both)만.** 카페/블로그/클립/밴드, 그리고 종토 **댓글
  (comment, URL 기반)**은 종목 개념이 없으므로 대상 아님(§2 범위 참고).

## 문제 / 요구

지금 게시명령에서 하위 선택 → 글/댓글 선택 → **종목토론방**을 누르면 종목이 **자동 선택**된다
(카테고리·시장·종목 수 N → 불꽃🔥 우선, 삼성전자·하이닉스 제외). 사용자는 종목을 **본인이 직접
고르는** 경로도 원한다.

원하는 동작:

- 종목토론방을 누르면 **버튼 2개**: `종목 자동선택` · `종목 수동선택`.
- **자동선택**: 지금 그대로 — 카테고리 / 시장 / 종목 수 N / (게시 후 내용변경) / 계정 선택.
  종목 수만 입력하면 불꽃 우선 자동 채움(삼성전자·하이닉스 제외).
- **수동선택**: 하위 데스크톱(pstmacro)의 **게시 설정 창 → 게시위치 → 종목 선택** 버튼을 눌렀을 때
  뜨는 그 **종목 선택 화면**을 재사용. 다 고르면 고른 종목이 뜨고, 그 아래 **게시 후 내용변경**
  체크박스, 그 아래 **계정 선택**, 그리고 게시.

**한 줄 요약**: `카테고리 / 시장 / 종목 수` **이 3개(=자동 산출)** 자리를, 자동이면 지금 UI 그대로,
수동이면 **종목 선택 모달로 고른 목록**으로 **갈아끼우는** 것. 그 아래(내용변경·계정·게시 버튼)는
양쪽 공통·불변.

## 2. 핵심 통찰 — 왜 이게 저위험인가

`ForumConfig`(자동선택 폼)은 이미 **클라이언트에서 종목을 실코드로 확정**한 뒤 게시 명령을 만든다:

- `pickStocks(pool, n)` → `picked: {code, name, isHotDiscussion}[]`
  (`src/admin/features/publish-command/publish-command.tsx:836`, 로직 `stock-select.ts:38`)
- `buildAssignments(split)` → `picked`를 계정에 배정해 `{loginId, stocks:[{code,name}]}[]` 생성
  (`publish-command.tsx:884`)
- `api.publish.send({ ..., assignments })` → 서버로 전송(`publish-command.tsx:910`, `api.ts:469`)

즉 **자동선택의 산출물은 이미 "명시적 종목 배열(`picked`)"**이다. 수동선택은 **그 `picked`를 모달로
고른 목록으로 채우기만** 하면, `buildAssignments` 이하 전 구간(계정·내용변경·즉시/예약/나눠서·전송·
스케줄러·하위 엔진)이 **한 줄도 안 바뀌고** 그대로 동작한다.

➡️ **게시 파이프라인(assignments→전송→스케줄러→하위 엔진)·types 변경 0.** 자동/수동 분기 자체는
순수 프론트다. **서버 변경은 딱 하나** — 수동 모달 검색을 위한 `fetch_search_page` 이식(§8-1). 검색을
빼면 서버도 완전 무변경.

## 6. 데이터 흐름 (수동 선택 경로)

```
사용자가 [종목 선택] → Admin 모달
  api.forumStocks.list({category,exchange,market,page})  ← 기존 서버 프록시 그대로
  → 행 렌더(체크) → [적용] → onConfirm([{code,name}, ...])
  → setManualStocks([...])
  → picked = manualStocks          ← 자동의 pickStocks 자리를 대체
  → buildAssignments(split)         ← 불변
  → api.publish.send({assignments}) ← 불변
```

자동 경로는 `picked = pickStocks(pool, n)` 그대로. **분기점은 `picked` 한 곳뿐.**

## 7. 게이트(활성 조건) 조정 — 유일하게 손대는 로직

기존 게이트는 `cfg.count`(종목 수) 기준(`publish-command.tsx:842~851`). 수동은 종목 수 입력이 없으니
`picked.length`로 바꿔 **양쪽 공통**으로 만든다:

- `allValid = postTitle!=null && picked.length>0 && cfg.accounts.length>0`
  (자동: N>0이면 picked>0이므로 동치. 수동: 고른 종목 수.)
- `canDistribute`(나눠서) = `allValid && accounts>=2 && picked.length>=2 && picked.length>=accounts`
  — 자동/수동 공통(이미 `picked.length` 기준이라 수동도 그대로 성립).

➡️ 나눠서 게시(균등분배)는 수동선택에서도 자동으로 동작(2개↑ 고르면 켜짐).

## 8. 확정 사항 + 남은 임의 결정

**정확히 구현 못하는 것: 없음.** 모든 조각이 기존 코드에 매핑된다(1~3·5~8 확정). 남은 임의결정은
버튼 배치·기본값 같은 사소한 것(§8-4)뿐 — 아래에 전부 표기.

**사용자 확정(2026-07-20):** ① 토글 위치·기본값 = 그대로(카테고리 위, 기본 자동). ② 수동 선택 종목
배지 위치 = 그대로(종목선택 버튼 아래). ③ 1시간 마커 = **그 하위 것만**(`api.postReports`를 deviceId로
필터). → 설계 100% 확정.

사용자 지시대로 **불확실·임의결정**을 전부 나열한다. 굵은 건 결정이 필요.

1. **종목 검색창 — 확정(불확실 없음): 데스크톱 `fetch_search_page` 40줄만 서버로 이식.**
   (사용자 확정 2026-07-20.) 데스크톱 검색은 `src-tauri/src/forum_stocks/client.rs:264`
   `fetch_search_page` → 네이버 `/front-api/search?q=...&size=SEARCH_SIZE&target=SEARCH_TARGET&page=`
   호출이며, **필터가 이미 박혀 있다**(client.rs:280~288):
   - `nationCode=="KOR" && category=="stock"` 아닌 항목 제외 → **국내 주식만**(해외·펀드/ETF 등 제외).
   - `looks_like_code(code)` 아닌 것 제외.
     나머지 검색 부속(🔥·숨김·원문캡처)은 **Admin 서버에 이미 전부 존재**하므로 새로 만들 필요 없다:

   | 부속                                                                   | 서버 위치(`server/src/naver_stocks.rs`) |
   | ---------------------------------------------------------------------- | --------------------------------------- |
   | `fetch_hot_codes`(🔥 집합, `/front-api/discussion/rankings/itemCodes`) | `:326`                                  |
   | `merge_hot`(🔥 마킹)                                                   | `:175`                                  |
   | `drop_hidden_stocks`+`is_hidden_stock`(ETN·레버리지 숨김 #267-7)       | `:165,:170`                             |
   | `looks_like_code`                                                      | `:142`                                  |
   | `get_json`(통신로그 원문 캡처 포함)                                    | `:202`                                  |

   ➡️ **서버에 없는 것은 `fetch_search_page`(≈40줄) 하나뿐.** 이식 후 `list()`와 대칭인 `search()` 래퍼
   (fetch_hot_codes → fetch_search_page → merge_hot → drop_hidden_stocks)를 추가하면 데스크톱과 **검색·
   필터·🔥·숨김 완전 동일**. 라우트는 `/admin/forum-stocks`에 `q` 파라미터 추가(있으면 search 경로),
   Admin `api.forumStocks.search(query,page)` 1개 추가. 🔥 채움 문제 없음(서버가 `fetch_hot_codes` 이미
   보유). 트레이드오프: §2 "순수 프론트"가 아니라 **정의된 소규모 서버 변경(검색 프록시 1개)** 이 더해짐.

2. **"1시간 내 게시성공" 마커 — 확정: 재사용(제거 아님).** 데스크톱은 종목 옆에 최근 1시간 게시성공
   표시를 로컬 로그(`ipc.logBatches`, `stock-crawl-modal.tsx:74~93,281`)로 그린다. **Admin에도 같은
   LogBatch/BatchItem 모델이 있으므로**(`api.ts:210~221`, `code`·`status` 포함) 동일 로직(forum·success·
   code·최근 1h)을 **Admin 배치 데이터에 연결하면 그대로 살아난다**. 라이브 소스는 이미 존재:
   `api.postReports`(서버 `/admin/post-reports`, `routes.rs:94`)가 같은 배치를 준다(그 하위 것만 보려면
   deviceId로 필터). 데이터 소스만 ipc→api(공유 추출 시 이 배치 조회도 주입 어댑터의 한 함수).
3. **거래소(krx/nxt) — 확정: 데스크톱 토글 그대로 재사용.** 데스크톱 모달 krx/nxt 토글 존재
   (`stock-crawl-modal.tsx:55,164`), Admin `api.forumStocks.list`가 `exchange` 인자 받음(`api.ts:458`),
   서버도 krx/nxt 파싱(`routes.rs:890` `Exchange::parse`). **nxt 끝단까지 이미 지원** → 수동 모달은 그
   토글을 그대로 가져온다(자동 흐름의 krx 하드코딩은 그 화면 한정, 무관).
4. **토글 위치·기본값** — 사용자가 요청한 `종목 자동선택 | 종목 수동선택` 2버튼(신규 기능이 아니라
   요구사항의 배치)을 카테고리 블록 **바로 위**, **기본=자동**(기존 동작 보존). 사소한 배치 — 원하면 변경.
5. **모달 재사용 방식 — 확정: 공유 컴포넌트 추출(A).** 데스크톱 `stock-crawl-modal.tsx`는 데이터를 Tauri
   `ipc.*`로 부르는데 웹 Admin엔 Tauri 런타임이 없어 **문자 그대로 import는 실행 불가**. UI(카테고리·시장·
   리스트·체크·🔥·검색·더보기)는 100% 동일 재사용, **데이터 호출부만 다름**(ipc↔api). 그래서 모달을
   **데이터 함수 주입형 공유 컴포넌트**로 추출 → 데스크톱은 ipc 어댑터, Admin은 api 어댑터 주입해 **같은
   파일을 양쪽이 재사용**한다. 데스크톱 변경은 데이터 호출을 어댑터로 빼는 소규모 리팩터(기존 테스트로
   회귀 방어). (대안 B=Admin 복제본은 데스크톱 무손상이나 파일 2개로 갈려 드리프트 — 미채택.)
6. **범위 — 종토 "댓글": pstmacro 설계로 확정(글·글+댓글만).** 데스크톱 자체가 종토 댓글에 종목 선택을
   **면제**한다 — "특정 게시글" 댓글은 URL이 곧 대상이고 종목코드까지 URL에 있음(`publish-modal.tsx:1351,
1519~1521`; `targetsOk = !forum || stockCodes>0 || forumUrlTargets>0`, `:1522`). 종목 선택 모달
   ("종목 선택" 버튼 `:303~312`)은 **글 게시 때만** 뜬다. 따라서 자동/수동 토글은 **글·글+댓글
   (ForumConfig)에만** 붙고 댓글(ForumCommentConfig=URL)은 그대로 — pstmacro 설계와 1:1 일치(임의해석 아님).
7. **수동에서 "종목 수 N" 필드** — 수동은 사용자가 직접 개수만큼 고르므로 N 입력칸 없음. `picked` =
   고른 개수. `count` 필드는 자동 전용. → 임의 결정.
8. **모달 종목 데이터의 카테고리/시장 기본값** — 데스크톱과 동일하게 카테고리=거래대금, 시장=전체,
   토론 카테고리는 시장 전체 고정. → 데스크톱 규칙 그대로.
