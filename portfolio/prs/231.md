## Summary

게시 큐(now 큐)에 **자동 우선순위**를 매겨 **로그인(1순위) → 종목토론방(2순위) → 카페/밴드(FIFO)**
순으로 실행한다. **삭제가 아니라 재정렬만** — 실행 중인 아이템은 끝까지 두고, 끝나면 우선순위 순으로
다음을 집는다. 게시 엔진/로그인/카페·밴드·종토 실행 로직·취소는 **불변(additive)**, **중복 게시 위험 0.**

사수 지침 1차 구현. 실행 중 작업의 안전지점 중지/재개는 후속 PR(Non-goals).

## Changes (`src-tauri/src/ipc/`)

- `queue.rs`
  - `item_priority(&QueueNowItem) -> u8` (순수): 로그인 전용(`plan.login` 있고 게시 타깃 없음)=0,
    `plan.forum` 포함=1, 그 외=2. 혼합 아이템도 forum 끼면 승격.
  - `apply_priority_order(items)` (순수): Running 맨 앞 고정 + Waiting 우선순위 **안정 정렬**
    (같은 등급은 FIFO·수동순서 보존).
  - `add_queue_now` / `reorder_queue_now` / promote 경로에 정렬 적용. 수동 드래그(`apply_reorder_now`)는
    등급 안에서만 유효(우선순위 우선).
- `queue_runner.rs`
  - `pick_next_waiting`: "첫 Waiting" → "최고 우선순위 Waiting"(동순위 FIFO)로 실행 순서를 못 박음.
