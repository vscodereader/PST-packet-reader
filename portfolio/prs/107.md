## PR 본문 원문

## 문제

IP 로테이션의 비행기모드 자동 토글이 Windows(삼성 갤럭시)에서 `adb USB ERROR: Access denied`로 동작하지 않음. `index`에서 `useAdb:true`로 켜면 로그인 흐름이 `assert_adb_device()`에서 그대로 죽음.

## 원인 (git 이력으로 확정)

- 커밋 `2075d4e feat(auth): replace scrcpy adb with adb_client`(2026-05-29)가 비행기모드 토글을 **표준 adb CLI → `adb_client` raw-USB**(`ADBUSBDevice::autodetect`)로 변경.
- raw-USB(nusb)는 **WinUSB 드라이버로 바인딩된 인터페이스만** 열 수 있는데, 삼성 폰 ADB 인터페이스는 제조사 전용 드라이버에 물려 있어 `Access denied`. (공식 `adb devices`는 정상 → 드라이버 문제임이 확정)
- 이 전환에는 **ADR이 없음** (docs/adr에 adb 관련 결정 문서 부재). 그 이전 표준 adb CLI 방식에서는 제조사 드라이버 그대로 동작했고 Zadig가 불필요했음.
- 참고: CDP 스텔스 작업(#102, fix/100)은 `adb.rs`를 건드리지 않아 본 회귀와 무관(별개 기능).

## 변경

- `assert_adb_device` / `toggle_airplane_mode` / `probe_adb_connection`을 `2075d4e` 이전의 **표준 adb CLI(`std::process::Command`)** 방식으로 복구. `winget Google.PlatformTools` adb가 PATH에 있으면 제조사 드라이버 그대로 동작 → **Zadig·새 UI 불필요**.
- `2075d4e` 이후 추가된 **IP 전후 로그 / 인터넷 복구 폴링 / 진단 probe는 그대로 보존**.
- 미사용이 된 `adb_client` 의존성(Cargo.toml) 및 `OrchestratorError::Adb` 변형 제거.
- 토글 인자·디바이스 인증 판별·인터넷 probe를 순수 함수로 추출해 단위 테스트 3종 추가.
