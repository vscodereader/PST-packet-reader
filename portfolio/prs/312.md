## 증상
블로그 댓글이 안 달림. 실제 에러: `블로그 글에서 groupId를 찾지 못했습니다` (백트레이스 `comment_client.rs:69` = `resolve_group_id`).

## 근본 원인 (패킷 분석으로 확정)
`~/packet_copy/블로그 주소 분석.pcapng`(TLS 복호화) + 라이브 재현으로 3-way 비교:

| 요청 주체 | 헤더 | 세션 | PostView 결과 |
|---|---|---|---|
| 익명 curl | 빈약 | 없음 | 200 + `var blogNo` ✅ |
| 로그인 브라우저(PCAP) | 풀 헤더 | 쿠키 | 200 + `var blogNo` ✅ |
| **앱**(`get_text`) | **UA+Cookie만** | 쿠키 | **200인데 `var blogNo` 없음** ❌ |

→ **쿠키가 아니라 요청 헤더가 원인.** 네이버는 *유효한 로그인 세션인데 브라우저 지문(Referer·sec-fetch 등)이 없는* `PostView.naver` 요청에 봇 인터스티셜(200이지만 `var blogNo` 없는 페이지)을 돌려준다. 그래서 `parse_group_id`가 None → 실패. 익명 요청은 "그냥 크롤러"라 통과돼 그동안 단위테스트/익명검증에선 안 잡혔다. 잘 되는 **카페** 경로는 이미 같은 이유로 위장 헤더(`naver_cafe/headers.rs`)를 싣는다 — 이 PR은 그 블로그 버전.

또한 패킷에서 **실제 댓글 작성 성공(code:1000)** 을 포착해 cbox token/create API 폼이 코드와 1:1 일치함을 확인했고, `groupId == blogNo`(objectId=`{blogNo}_201_{logNo}`)도 재확인했다. 즉 API 흐름은 정상이고 문제는 1단계 HTML 조회의 헤더뿐이었다.

## 변경
- **`naver_blog/headers.rs` 신설** — `blog_document_headers`(글 조회/목록 = navigate/document), `blog_cbox_headers`(cbox XHR = same-site/cors). Referer만 호출부가 정함.
- **`comment_client`** — `get_text`가 헤더 세트를 받게 하고 `resolve_group_id`·`fetch_cbox_token`·`post_blog_comment`에 각각 적용(Referer = 블로그 홈/글 주소).
- **`post_list`** — 글 목록 GET에도 동일 위장 헤더(대칭).
- **진단** — `parse_group_id` 실패 시 응답길이+앞부분 스니펫(쿠키 없음)을 메시지에 남겨 재발 시 봇차단/빈응답을 구분. `response_diagnostic` 순수함수.

## 테스트
- `cargo test --lib naver_blog` → 31 passed (위장 헤더 전송·진단 스니펫·기존 흐름 포함). clippy 신규 경고 없음.
- ⚠️ **실제 통과는 빌드 후 로그인 세션으로 재확인 필요** — 헤더 없이는 봇차단이 재현되지 않아(익명은 통과) 단위테스트로 100% 보장 불가. 그래서 진단 로그를 동봉했다.
