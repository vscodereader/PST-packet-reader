## Summary
사용자 실측 패킷(`프로필 생성하기 전`=lhssi 계정, `동의+프로필까지`) 대조로, 종토 프로필/약관 요청이 실패하던 근본원인이 **네이버 봇탐지(UMON) 유발 = 우리 요청 헤더/인코딩이 브라우저와 달랐던 것**임을 확정하고 브라우저와 일치시킨다. (게시=100% 패킷 유지, 페이지 이동 없음.)

- **client-hints 추가**(`sec-ch-ua`/`-mobile`/`-platform`): 브라우저는 모든 요청에 보내는데 우리가 안 보내 봇 판정. `sec-ch-ua` 버전은 UA의 Chrome 버전과 일치(불일치도 봇 신호). base_headers + npay navigation 양쪽.
- **GET에서 `origin` 헤더 제거**: 브라우저는 같은 출처 GET(`/profile/users/status`·`/form`)에 Origin을 안 보냄. 우리가 붙여 `403 UMON_PERMANENT_BANNED`(가짜 밴 — lhssi는 브라우저 200으로 멀쩡)·프로필 500 유발. POST/PUT은 그대로 Origin 유지.
- **accept-encoding을 브라우저와 일치**(gzip, deflate, br, **zstd**): reqwest 기능(brotli/deflate/zstd) 켜서 광고+자동 디코딩. gzip만 보내던 지문 불일치 제거(사수 지적: 네이버 zstd 사용).
- **쿠키 완전수거**(`Network.getAllCookies`, login·post 양쪽): URL 필터 방식은 nid 세션쿠키(`NID_JST` 등 `.nid.naver.com` host-only)를 놓쳐 commonTermAgree 튕김을 유발. 밴드 로그인과 동일하게 전량 수거 후 naver 도메인만 필터.
- **진단 프로브 제거**(`debug_probe_profile_status`): 매 `/status`마다 중복 호출하던 임시 진단 코드 제거 — 사수 지적 "불필요한 API 호출". 원인 규명(헤더)이 끝나 역할 종료.
