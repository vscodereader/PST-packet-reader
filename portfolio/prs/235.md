# Summary

본문(글)·댓글에 **여러 줄을 쓰면 한 줄로 붙어서 게시**되던 문제를 고친다. 예를 들어 본문에
```
엥 이거 진짜로?
#{링크}
```
처럼 쓰면 `엥 이거 진짜로?https://링크`처럼 줄바꿈이 사라지고 링크가 앞 줄 끝에 그대로 달라붙었다.

## Root cause

`naver_automation/post_form.rs`의 contenteditable 입력에서 `document.execCommand('insertText', false, value)`를 쓰는데, **`insertText`는 `'\n'`을 줄바꿈으로 만들지 않는다** — 여러 줄이 한 줄로 붙는다. 게다가 `insertText`가 `true`를 반환해, `'\n'`을 `<br>`로 바꿔주는 기존 fallback(`split('\n')` + `<br>`)에 **도달하지 못하고** native 경로로 바로 끝났다.

토큰 치환(`#{링크}` 등)은 단순 `.replace()`라 줄바꿈을 보존하고, `htmlToText`도 보존한다(검증 완료). 줄바꿈은 본문 문자열에 끝까지 살아있다가 **이 입력 단계에서만** 유실됐다.

## Fix

단일 `insertText` 대신 **줄 단위로 `insertText`하고 줄 사이마다 `insertLineBreak`로 실제 줄바꿈**을 만든다. native 입력 이벤트(`fire(editor)`)는 그대로라 SmartEditor 호환을 유지하고, 한 줄 본문은 기존과 동일하게 `insertText` 1회로 동작한다.

- 본문 입력부(`fill_modal_post_form`의 `setEditorValue`)
- 댓글 입력부(`fill_comment_editor`의 `setEditorValue`)

두 곳 모두 동일 패턴으로 수정. **종목토론방·카페 공통 경로**라 둘 다 해결된다.

## Test

- 브라우저 주입 JS(실제 Chrome/CDP 실행)라 Rust 단위테스트 대상이 아니다. `cargo build --lib` 컴파일 통과(`format!` brace 이스케이프 검증), clippy·fmt clean.
- e2e(앱 실행)는 작성자 직접: 본문/댓글에 줄바꿈 + `#{링크}`를 넣고 게시 → 줄바꿈이 그대로 올라가는지 확인.
