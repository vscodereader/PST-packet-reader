## 배경 (사수 지적)
로그 파일엔 `discussion_batch`의 **요약 로그**("대기초과 N/9 재시도", "실패 ❌ — 대기시간 초과")만 남고, **실제 네이버 API 호출의 성공/실패**(status·body·백트레이스에 들어가는 내용)는 안 남았습니다. 원인: 게시 엔진 4개 파일(`packet_client`/`post_form`/`discussion_room`/`browser_flow`)에 `tracing` 호출이 **0줄**. 실패 정보는 `AutomationError`에만 담겨 UI '자세히 보기'로만 갔습니다.

또한 "게시 시작까지 20초 + 시작하자마자 대기초과 1/9"의 진짜 단계가 가려져 있었습니다(= `wait_for_ready_state` 페이지 로드 타임아웃, API 미호출).

## 변경 (동작 변경 없음 — 로깅만 추가)
- **`response_text`**(모든 GET/POST/PUT 단일 통로): 실제 API 응답 OK / HTTP 실패 `status`+`body` 기록 — 예) 프로필 상태 `status=500 body={"message":"Failed to fetch profile user status"}`
- **`get_stock_json`**: 호출 직전 API 경로(`GET /api/...`) + 전송 계층 실패 기록
- **`post_with_retry`**: HTTP `status`+`elapsed_ms`, 429/5xx 재시도·최종 실패
- **`submit_post`/`submit_comment`**: add/cbox API-level `isSuccess` 성공(`post_id`)·실패(body)
- **`run_naver_discussion_macro`**: 매크로 시작~세션 오픈 소요초("20초" 출처 가시화)
- **`wait_for_ready_state`**: 타임아웃 시 멈춘 `url`·마지막 `readyState` + **CDP Network 이벤트 기반 멈춘/실패 브라우저 요청 목록**
- **`CdpClient`**: 게시/댓글 경로에서 `Network.enable` + `requestWillBeSent`/`responseReceived`/`loadingFinished`/`loadingFailed` 이벤트 수집(로그인 `enable_page_only`은 봇탐지 표면 유지 위해 **미변경**)
- **`discussion_batch`** `[POST]` 실패 줄에 백트레이스(`trace`) 동봉

refactor(post): 종토방 게시에서 브라우저 페이지 이동·로드 대기 제거 — 순수 패킷 API로 게시

글쓰기/댓글은 이미 HTTP 패킷 API(글쓰기 form→add, cbox 댓글)로 처리되는데,
종목토론방 페이지로의 브라우저 이동 + 전체 로드 대기(wait_for_ready_state)가
레거시로 남아 있어 ① 게시당 ~20초 지연 ② 페이지의 Next.js 청크가 끝까지
로딩 안 되면 가짜 "대기초과"를 유발했다(사수 지적 2026-06-30).

- open_discussion_session: ensure_discussion_page·discussion-room 이동 제거.
  Chrome은 쿠키 추출(Network.getCookies)·로그인 확인(getProfile)까지만 사용.
  종목토론방 URL은 종목 코드로 직접 생성(선택)하거나 select_random_discussion_room
  패킷 API로 선택(랜덤) — 예전 current_url()이 돌려주던 값과 동일.
- run_naver_discussion_macro / run_naver_post_with_comment_macro: submit_post/
  post_url_from_id/select_random_discussion_post/submit_comment를 구성한 URL로
  직접 호출. reload_after_submit(게시 후 새로고침) 제거.
- 세션 만료 감지는 페이지 리다이렉트(nid.naver.com) 대신 getProfile 결과로.
- 수동 확인 모드(CLI submit_after_fill=false)만 브라우저 폼이 필요해 그 경로에서만
  navigate한다.

이로써 discussion_room의 이동 함수들과 post_form의 *_and_refresh, browser_flow의
npay/ensure_discussion_page가 미사용(연결 끊김)이 된다 — 사수가 지적한 "끊겨야
하는데 살아있던 기존 코드"가 실제로 끊긴 것(컴파일 dead_code 경고로 확인). 정리
삭제는 후속.

주의: 네이버페이 약관 미동의 계정의 브라우저 기반 처리(handle_npay_agreement)는
이 경로에서 빠진다 — 미동의 계정은 API 단계 실패로 드러난다.
