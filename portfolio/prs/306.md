## Summary

- `ARTICLE_LIST_TRANSPORT_ERROR` 등 전송 오류가 reqwest wrapper(`error sending request for url ...`)만 찍어 **진짜 원인(연결거부/리셋/타임아웃/DNS)이 `source()` 체인에 숨겨져** "뭐가 문제인지" 알 수 없던 문제.
- `util`에 공용 추가: `describe_reqwest_error`(분류 + source() 원인 체인 = **A**) + 매크로 `transport_error_message!`(A + `here!` 위치앵커 + `backtrace_string()` = **B**, "자세히 보기" trace 노출). POST 경로가 쓰던 패턴을 일반화.
- 적용: 카페(article_list×2·cafe_ref·home×2·joined_cafes·menu·post·comment) + 블로그(post_list·comment×2). 읽기 클라이언트 전부 통일.
- **동작 불변**: 에러 `code`/`retryable`/제어흐름/성공경로 그대로. `message`는 표시(trace)용이며, 계정 Blocked/TimedOut 라우팅(`is_blocking_failure`/`is_timed_out_failure`)은 **forum(종토) 결과만** 보고 카페/블로그는 대상 아님(`queue_runner.rs` 주석·코드로 확인) → 라우팅 영향 0.
