## 배경
사수 지시: 로그인 시 캡차가 계속 뜨는 건 DOM이 끝까지 로드되기 전에 진행하기 때문.
**로그인 폼 대기**와 **결과 폴링** 둘 다 "돔이 싹 다 붙을 때까지" 기다려야 한다.

직전 작업에서 **폼 대기(`wait_for_login_form`)** 는 상위문서 + 모든 iframe complete +
연속 안정(3회)으로 이미 충족했으나, **클릭 후 결과 폴링**은 settle 0.8초 + 신호 2회
latch만 보고 DOM 완전 로드를 확인하지 않았다 — 이 누락분을 채운다.

## 변경
- 결과 루프에 **상위문서 + 모든 iframe `readyState==='complete'` 연속 안정(3회)** 게이트
  추가(`ALL_DOCS_COMPLETE_JS` + `result_dom_gate_open`). 게이트가 열릴 때까지 비번오류/
  차단/캡차 판정을 미뤄 네비게이션 과도기의 덜 그려진 DOM에서 결과를 오판하지 않는다.
- **성공(세션 쿠키)은 게이트와 무관하게 즉시 확정** — naver.com 광고 iframe 로딩을
  기다리느라 정상 로그인을 늦추거나 놓치지 않는다.
- 교차 출처 iframe은 검사 불가라 통과(폼 대기와 동일 규약). 전체 deadline이 무한대기 방지.

## 테스트
- `result_dom_gate_open` 순수 함수 + 단위 테스트 2건(임계치 게이트 / 과도기 리셋).
- `cargo test --lib auth::login_flow` 통과, clippy(login_flow) 깨끗.

기존 폼 대기·신호 분류·캡차 grace 로직은 그대로 두고 게이트만 additive로 추가.

안정으로 "돔 끝까지" 기다렸지만, 클릭 후 결과 폴링은 settle 0.8초+신호
2회 latch만 보고 DOM 완전 로드를 확인하지 않았다(누락분).

사수 지시대로 결과 폴링에도 동일 게이트를 추가한다: 착지 페이지의 상위
문서+모든 iframe이 complete로 연속 RESULT_DOM_STABLE_POLLS(3)회 안정될
때까지 비번오류/차단/캡차 판정을 미뤄, 네비게이션 과도기의 덜 그려진
DOM에서 결과를 오판(조기 캡차/차단 확정)하지 않게 한다.

성공(세션 쿠키)은 DOM 게이트와 무관하게 즉시 확정 — naver.com 광고 iframe
로딩을 기다리느라 정상 로그인을 늦추거나 놓치지 않는다. 전체 deadline이
무한 대기를 막는다. 교차 출처 iframe은 검사 불가라 통과(폼 대기와 동일 규약).

result_dom_gate_open 순수 함수 + 단위 테스트 2건 추가.
