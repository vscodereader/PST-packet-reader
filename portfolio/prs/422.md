fix(report): inject session cookies into token browser before navigate

The report token browser opened a fresh Chrome with no login session, so
the srp2 report page redirected to nid.naver.com/nidlogin.login and the
ncaptcha token JS returned empty for every poll ("토큰 획득 실패", live CDP
log 2026-07-14).

Add CdpClient::set_naver_cookies, which enables the Network domain and
sends Network.setCookies with the account's saved Naver cookies
(.naver.com / path=/ / secure). TokenBrowser::open now injects these
after connecting CDP and before navigating to the report page, so the
page renders logged in and the SDK can mint the token.

Cookie values are credentials: only names/count are logged, and
redact_cdp_params masks the Network.setCookies value field in the raw
CDP wire trace.
