## PR 본문 원문

tshark 패킷 분석으로 '동의하기'의 실제 동작을 확인: **체크박스가 아니라 네이버페이 금융서비스 가입 GET 리다이렉트 체인**.

\`member-web.pay.naver.com/financial-service/join?...consent=N...\` → 302 → \`nid commonTermAgree(termcd=40)\` → \`naver-term-consent/callback\` → 가입완료. CSRF 없음·쿠키 인증·선택동의(마케팅/마이데이터/머니스토리) 전부 N.

## 변경 (기존 코드 보존)
- \`handle_npay_agreement_if_present\`: ⒜ **가입 URL로 직접 navigate**(주 경로, DOM 무관·견고) → ⒝ 그래도 약관 페이지면 **기존 체크박스 동의 로직을 폴백으로 그대로** 실행. navigate/wait/current_url 기존 함수 재사용.
- 흐름 유지: **동의(가입) → 프로필 생성(기존 ensure_profile_intro_setup) → 패킷 게시** 순서 그대로. 가입 완료/폴백 시도 후에만 다음 단계 진행.
- 커뮤니티 프로필 생성은 이미 packet_client가 처리 중 → 무수정.
