## 문제
어제(2026-07-02) 야간 배치에서 **로그인 후 방치했다가 아침에 좋아요를 누르면 전 계정이 실패**했습니다.
로그: `반응 생성` HTTP **400**, `errorCode 400Z01 "[NidHeader] Nid-No is required"`. 수동 재로그인하면 정상.

## 근본 원인
좋아요 직전 `run_naver_like`가 **무조건** `ensure_npay_financial_join()`(네이버페이 동의)을 호출하는데,
세션이 살짝 만료되면 이 요청이 `nidlogin.login`으로 튕기고, `packet_client`의
`self.cookies = rotated_cookies;` 가 **튕김 여부와 무관하게** 회전 쿠키(빈 `NID_AUT`)를 덮어써
유효 세션을 스스로 파괴 → 이어지는 좋아요 POST가 인증쿠키 없이 나가 400. (실측 로그 `nid_aut_after=e`)

실측 패킷(`packet_copy/좋아요 싫어요/*.pcapng`) 확인: 좋아요 POST는 `Nid-No` 헤더 없이 **순수 로그인
쿠키(NID_AUT/NID_SES/BUC/nid_inf)만으로 인증**되고, 프로필 생성·npay 가입 호출 없이 이미 가입된 계정은
바로 눌립니다. 즉 정상 좋아요는 npay를 타지 않습니다.

## 수정 (게시 경로 무손상)
- **신규 `naver_automation/like_flow.rs`** — 좋아요 전용 경로:
  0. 좋아요 직전 `read_login_profile()`(순수 getProfile API)로 **세션 생존 확인** → 로그아웃이면
     npay·좋아요 시도 없이 "재로그인 필요"로 반환(쿠키 훼손 0, 멀쩡한 계정은 불필요한 로그인·캡차 회피).
  1. 살아있으면 그대로 좋아요.
  2. '미가입' 실패 시에만 **쿠키 보존 npay** 후 1회 재시도.
  3. 만료 신호(`Nid-No`/`400Z01`/`nidlogin.login`)면 원본 쿠키 지킨 채 "재로그인 필요".
- **`packet_client`**: `try_npay_join_preserving_cookies()` 추가 — 가입 **완료(Completed) 시에만** 회전
  쿠키 반영, 로그인 튕김/약관 멈춤이면 **원본 쿠키 보존**. 게시용 `ensure_npay_financial_join`은 **무변경**.
- **인증 쿠키 원문 로깅** 추가(NID_AUT/NID_SES/BUC): 좋아요 로드 / npay 전후 / 재로그인 저장 시점.
  ⚠️ 살아있는 세션 토큰이라 로그 파일은 민감정보.
