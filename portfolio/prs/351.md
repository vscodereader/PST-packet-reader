## 배경 (fix_and_add 4번)
로그인 자동화 중 사용자가 아무것도 안 하면 Chrome 주소창(omnibox)이 포커스/전체선택된 채로 있고 캡차가 더 자주 떴다. 사용자가 빈 화면을 **한 번 클릭**하면 주소창 선택이 풀리고 캡차 빈도가 급감했다.

## 근본 원인
CDP 입력은 렌더러 DOM의 `activeElement`만 바꿀 뿐 **브라우저(창) 포커스는 omnibox에 그대로** 둔다. Chrome이 `about:blank`로 떠서 주소창이 포커스된 채 시작하고, `Page.navigate` 후에도 포커스를 문서로 옮기는 호출이 코드에 없어 `document.hasFocus()`가 로그인 내내 false다. 네이버 wtm 안티봇은 "한 번도 포커스되지 않은 페이지"를 봇 신호로 읽어 캡차를 올린다. 실클릭은 그 포커스를 문서로 옮기고 포인터 엔트로피를 줘 신호를 없앤다.

## 변경
폼 로딩 확인 직후·타이핑 전에 `focus_web_contents()`:
1. `Page.bringToFront` — 창 포커스를 웹 컨텐츠로(주소창 선택 해제).
2. `neutral_body_point()` + `mouse_click` — 폼/버튼/링크와 겹치지 않는 빈 좌표를 진짜 마우스로 클릭(`elementFromPoint`로 안전 지점 선별 → 링크 오클릭 방지).

모두 best-effort(실패해도 로그인 진행). 적용 전후 `document.hasFocus()`를 로그로 남겨 효과 검증. Page 도메인은 이미 `enable_page_only`로 켜져 있고 Input도 기존 클릭에 쓰므로 CDP 탐지표면 증가는 사실상 없음(Runtime.enable 회피 설계 유지).
