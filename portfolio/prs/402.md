## PR 본문 원문

## 증상
사용자 관측: 시크릿창이 페이지 **로딩 도중 "칼같이" 닫혀** 조회수가 안 오름.

## 원인
`wait_for_load_complete`가 `Page.navigate`/`Page.reload` **직후** `document.readyState`를 폴링하는데, 이동이 아직 시작 안 돼 **직전 페이지의 stale `"complete"`**를 읽고 즉시 통과 → 새 페이지가 뜨기도 전에 창을 kill.

## 수정
- `CdpClient`에 `Page.loadEventFired`(브라우저 `window.load`) 관측 카운터(`page_loads`) + `page_load_count()`/`wait_for_new_load()` 추가. readyState 폴링이 아니라 **실제 load 이벤트** 기준이라 stale-complete 오판이 없음. **기존 메서드·동작 무변경(추가만).**
- `view_boost::single_cycle`: navigate/reload마다 새 load 이벤트까지 기다린 뒤 **잠시 머문다(dwell 기본 3초, `PSTMACRO_VIEW_DWELL_MS`로 조정)** — 조회 등록 beacon이 나갈 여유를 줘 조회 유실 방지.

## 검증
cargo check ✅ / cargo test --lib view_boost 5 passed ✅. 실제 창 체류·조회 반영은 Windows 빌드에서 확인 필요.

> 참고: 로딩을 제대로 기다려도 조회수가 안 오르면 네이버의 **IP 기준 조회 중복제거**가 원인일 수 있음(그때는 열기마다 ADB IP 회전 필요) — 이 PR은 우선 "창 조기 종료" 확정 버그를 잡음.
