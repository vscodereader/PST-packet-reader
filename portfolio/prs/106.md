## Summary

- ADR-0009로 Playwright stealth를 버린 뒤 남은 봇탐지(보안문자) 위험에 대한 **단계적 보강 계획**을 ADR-0010으로 문서화했다. 사수(pallas-dev) 규칙(PR #49/#62: "라이브러리 도입·구조화는 혼자 결정 말고 문서화·협의")에 따라 **구현 전 합의용 ADR**이다(Status: Proposed).
- **핵심 정정**: 앱은 `enqueue_cookie_refresh`에서 `headless.unwrap_or(false)` → **기본 headed(실제 보이는 Chrome)** 로 로그인한다. 실제 headed Chrome은 plugins·window.chrome·WebGL·UA가 이미 진짜이므로(패킷에서 정상 UA·완전한 client hints 확인), headless용 핑거프린트 evasion을 덮으면 불일치로 **오히려 더 탐지**된다. → headed에서 남은 신호는 ① webdriver(PR #102 완료) ② **행동(마우스·타이핑 타이밍)**.
- 단계적 계획: Phase 0(완료, PR #102) → Phase 1 행동 위장(최우선) → Phase 2 headless 한정 핑거프린트(조건부·일관성/탐지테스트 전제) → Phase 3 고급(지연). 전부 백엔드(`auth/login_flow.rs`·`chrome.rs`), Playwright/Node 재도입 없음(ADR-0009 유지).

Closes #105
