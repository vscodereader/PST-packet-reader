패킷 복호화(2026-07-14, 가입/예약+공개범위/이미생성된블로그 pcap, tshark+keylog)로 네이버
RabbitWrite의 실측 openType wire 값 확정: **2=전체공개**(기본값·searchYn/outSideAllowYn true),
1=이웃, 0=비공개. UI 표시 순서(0=전체…3=비공개)와 다르다.

- OpenType::code()가 UI 순서를 그대로 wire 값으로 보내 전체공개를 0으로 전송 → 네이버가 0을
  비공개로 해석 → "전체공개로 골라도 비공개로 발행"되던 버그. Public→2, Neighbor→1, Private→0으로
  실측값 교정. 서로이웃(MutualNeighbor)은 캡처 미확보라 이웃(1)과 같은 버킷으로 잠정 처리(공개 유출
  없는 안전값). 로컬·Admin 둘 다 이 code()를 타므로 한 곳 수정으로 양쪽 해결.
- 참고: di/autoSaveNo/tokenId는 무관(tokenId는 클라 랜덤 nonce라 우리 구현이 실측과 동일). editorSource도
  이미 정상 전송 중 — 유일한 원인은 openType 숫자였다.

- Admin 원격 발행(run_blog_write_command)이 결과를 서버로만 회신하고 하위 pstmacro 로컬 알림엔
  기록하지 않던 문제 수정 — app을 배선해 데스크톱 직접 발행과 동일하게 활동(시스템) 알림에
  성공/실패를 기록. 서버 post_report는 유지(ADD ONLY).
