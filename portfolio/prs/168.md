## Summary

- 기존 `tracing_appender::rolling::daily`는 로그 파일 핸들을 프로세스 수명 동안 잡고 **날짜가 바뀔 때만** 새 파일을 만들어, 실행 중에 로그 파일을 지우면(로그가 너무 길어 그 시점부터만 보려는 경우) 앱 재시작 전까지 새 로그가 기록되지 않았다.
- self-healing 일자별 writer(`SelfHealingDailyWriter`)로 교체해, 매 기록 시 당일 파일 존재를 확인하고 **외부에서 지워졌으면 같은 날짜 파일을 자동 재생성**(self-heal)한다. 파일명(`pstmacro.log.YYYY-MM-DD`)·append·non_blocking·형식/prefix/콘솔 레이어·env_filter 등 기존 동작은 그대로 유지하는 additive 변경(appender 구현만 교체).

Closes #166

## 변경 범위

**수정 (additive — 동작 보존)**
- `src-tauri/src/logging.rs` — `SelfHealingDailyWriter`(`io::Write`) + 재오픈 판정 순수 함수 `should_reopen` 추가. `init_file_logging`의 appender만 교체하고 형식/prefix/콘솔 레이어/env_filter는 불변.

## 설계 결정

- 날짜 suffix는 `LocalTimer`와 동일하게 `chrono::Local` 기준 → "오늘 날짜" 파일이 직관적으로 생긴다.
- 재오픈 판정(`should_reopen`)을 순수 함수로 분리해 단위 테스트(첫 기록 / 같은날 존재 / 외부삭제 / 날짜변경 4케이스).
