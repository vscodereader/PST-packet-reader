## 배경

`auth::config::tests::chrome_path_prefers_existing_env_override`의 세 번째 단언이
"테스트 호스트엔 Chrome이 없다"고 가정해 `chrome_path().is_err()`를 검사했습니다.
하지만 **WSL 호스트**에서는 플랫폼 기본 경로가
`/mnt/c/Program Files/Google/Chrome/Application/chrome.exe`이고, Windows Chrome이
설치돼 있으면 이 경로가 실제로 존재합니다. 그래서 `chrome_path()`가 `Ok`를 반환해
로컬 `cargo test`가 1개 실패합니다(비-WSL ubuntu 러너인 CI는 통과).

## 변경

- 호스트에 의존하지 않도록, 세 번째 단언을 **실제 계약**으로 교체:
  `chrome_path().is_ok() == (플랫폼 기본 경로가 존재)`.
- `chrome_path()` 프로덕션 동작은 **변경 없음**. 테스트의 잘못된 가정만 수정.
- 기존 두 단언(존재하는 `CHROME_PATH` 채택 / 없는 경로 오류)은 그대로 유지.

test(auth): make chrome_path fallback assertion host-independent

The third assertion in chrome_path_prefers_existing_env_override assumed the
test host has no Chrome at the platform-default path. On WSL the default is
/mnt/c/Program Files/Google/Chrome/Application/chrome.exe, which exists when
Windows Chrome is installed, so chrome_path() returns Ok and the is_err()
assertion fails locally (CI on non-WSL ubuntu still passes).

Assert the actual contract instead — chrome_path() is Ok iff the platform
default path exists — so the test holds on any host. chrome_path() behavior
is unchanged.
