## 배경
`#id` 자동입력이 **"포커스 정상 · keydown 후킹 로드됨 · 그런데 value 0글자"** 로 실패할 때, 기존 진단(`fill_diag_cause`)은 원인을 `미상`으로만 남겨 두 가설을 구분하지 못했다:

- **가설 A** — 네이버 안티봇이 합성 keydown의 기본동작을 `preventDefault`로 차단해 글자가 value에 안 박힘
- **가설 B** — 입력칸이 `readOnly`(폼이 JS로 잠금 해제하기 전 타이핑)

`disabled`만 보고 `readOnly`는 검사하지 않았고, `preventDefault` 여부는 전혀 관측하지 않아 다음 실패에서도 똑같이 "미상"만 떴다.

## 변경
- `FillDiag`에 `read_only`, `default_prevented`(tri-state: 차단/정상/미관측) 추가
- `type_into` 진입 시 document 버블 단계 keydown **recorder를 best-effort 설치** → 마지막 keydown의 `defaultPrevented`를 관측하고, 실패 tail에서 `readOnly`와 함께 스냅샷
- `fill_diag_cause` 우선순위에 **가설 B(readOnly) → 가설 A(preventDefault)** 분기 삽입
- `format_fill_diag` 출력에 `readOnly` / `preventDefault` 라인 노출
- 단위테스트 3종 추가(readOnly 우선 / preventDefault=차단 / 차단아님→미상)

## 위험도
**진단 보강만** — 실제 키 입력 경로(`Input.dispatchKeyEvent`)는 그대로다. recorder 설치는 `let _ =`(best-effort)라 실패해도 로그인에 영향 없음. navigate로 페이지가 새로 뜨면 `window` 상태가 초기화돼 로그인 간 누수 없음.

## 효과
다음 자동입력 실패 시 "자세히 보기"가 A/B를 자동으로 가른다 → 후속 픽스(A=insertText 폴백·후킹 우회 / B=readonly 해제 대기) 방향을 증거로 결정 가능.
