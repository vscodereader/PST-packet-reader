## PR 본문 원문

## 문제
게시(종토방 글/댓글)가 **외부 Chrome 9222 포트에 붙는** 방식이라, 사용자가 직접 `--remote-debugging-port=9222`로 Chrome을 띄워야만 동작했습니다(안 그러면 `127.0.0.1:9222 연결 실패, os error 10061`). 배포 사용자는 이걸 모릅니다.

## 수정 (최소)
`run_forum_publish_now`가 **로그인과 동일한 Chrome 런처(`auth::chrome::launch`, 헤드리스)** 를 재사용해 디버그 포트 Chrome을 앱이 직접 띄우고, 게시를 그 포트로 보낸 뒤 핸들 Drop으로 Chrome을 종료합니다. **사용자는 포트를 전혀 신경 쓸 필요 없음** → 로그인 → 게시하기 → 자동 게시.

- 변경: `src-tauri/src/lib.rs`(run_forum_publish_now), `src-tauri/src/auth/mod.rs`(런처 재노출 1줄). 엔진/로그인 로직은 그대로.
- rust 128+8 테스트·clippy·fmt 통과.

@pallas-dev 게시 엔진(`connect_to_existing_chrome`)은 제가 #59로 올린 코드라 자체 수정했고, UI가 넘기던 host/port는 백엔드가 자동으로 정하게 바꿨습니다. 검토 부탁드립니다.

fix(forum): auto-launch debug Chrome for posting (no manual 9222)

Posting connected to an external Chrome on 127.0.0.1:9222, so users had to
launch Chrome with --remote-debugging-port=9222 themselves or posting failed
(os error 10061). run_forum_publish_now now reuses the login Chrome launcher
(auth::chrome::launch, headless) to start a managed debug-port Chrome, routes
the publish to that port, and drops the handle (closing Chrome) when done.
Users no longer touch any port. Engine/login code unchanged otherwise.
