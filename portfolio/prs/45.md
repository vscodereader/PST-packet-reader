## 작업 배경

네이버 증권 토론 자동화 기능을 기존 CLI 중심 흐름에서 실제 사용자가 화면에서 CSV를 가져오고, 종목과 실행 조건을 선택한 뒤 실행할 수 있는 batch UI 구조로 확장했습니다.

또한 Chrome 페이지 안에서 JavaScript fetch를 실행하는 방식이 아니라, Rust reqwest 클라이언트가 로그인된 Chrome 세션의 쿠키를 사용해 네이버 API 요청을 직접 보내는 구조로 전환했습니다.

Windows 배포판 기준으로는 사용자가 Chrome DevTools host/port나 WSL IP를 직접 입력하지 않도록 하고, 시크릿 Chrome 열기 버튼을 통해 자동화용 Chrome을 실행하는 흐름으로 정리했습니다.

## 주요 변경 사항

### 1. Rust 패킷 클라이언트 전환

- Chrome DevTools는 로그인 세션 쿠키 추출과 화면 이동에만 사용합니다.
- 실제 글쓰기/댓글 HTTP 요청은 Rust reqwest 클라이언트가 직접 전송합니다.
- 네이버 로그인 쿠키는 코드에 저장하지 않고, 실행 시점에 Chrome 세션에서 읽습니다.
- NID_AUT, NID_SES 쿠키가 없으면 로그인되지 않은 상태로 보고 실행을 중단합니다.
- 글쓰기는 /front-api/discussion/form 패킷으로 txId를 발급받은 뒤 /front-api/discussion/add 패킷에 넣어 등록합니다.
- 댓글은 cbox token 발급 패킷을 먼저 호출한 뒤 댓글 생성 패킷에 token과 내용을 넣어 등록합니다.

### 2. 패킷 기반 자동화 함수화

- 로그인 확인을 getProfile 패킷 기반 함수로 구현했습니다.
- 랜덤 종목 선택을 네이버 증권 API 응답 기반으로 전환했습니다.
- 랜덤 게시글 선택을 posts/by-item API 응답 기반으로 전환했습니다.
- 프로필 소개 2222 설정을 status, form, introduction/validate, PUT users/<profileId> 패킷 흐름으로 전환했습니다.
- 글쓰기 등록과 댓글 등록을 Rust 패킷 함수로 분리했습니다.
- 자동 제출 경로에서 핵심 서버 요청은 DOM 조작이 아니라 Rust 패킷 함수가 담당하도록 정리했습니다.

### 3. CSV 기반 batch UI 추가

- CSV 파일에서 제목, 내용, 댓글내용을 가져오는 UI를 추가했습니다.
- CSV 첫 행은 헤더로 처리하고, 2행부터 실제 데이터로 사용합니다.
- 종목 검색 및 종목 선택 UI를 추가했습니다.
- 선택된 종목은 종목명, 6자리 종목코드, 토론방 링크를 확인할 수 있게 했습니다.
- 글쓰기/댓글쓰기 체크박스를 추가했습니다.
- 아무 행동도 선택하지 않으면 오류와 빨간 테두리를 표시하도록 했습니다.
- 제목/내용/댓글내용 각각에 대해 랜덤, 순차, 1개만 선택 방식을 추가했습니다.
- 1개만은 값이 정확히 하나일 때만 선택할 수 있도록 했습니다.
- 작성 개수는 3개, 5개 중 선택하도록 했습니다.
- 등록 사이에는 1분 대기하도록 Rust 실행기에서 처리합니다.
- 실제 실행은 프론트가 직접 요청하지 않고, Tauri command를 통해 Rust 함수가 수행합니다.

### 4. Windows 시크릿 Chrome 배포 흐름 추가

- Windows 배포판 기준으로 일반 Chrome이 아니라 자동화용 시크릿 Chrome을 사용하도록 했습니다.
- 사용자 화면에서는 DevTools host/port 입력창과 Windows/WSL 선택 UI를 숨겼습니다.
- 대신 시크릿 Chrome 열기 버튼만 노출합니다.
- Windows 배포판 내부 기본값은 127.0.0.1:9222를 사용합니다.
- WSL 개발환경에서는 기존 개발 편의를 위해 내부적으로 172.24.32.1:9223 값을 유지합니다.
- 시크릿 Chrome은 별도 user-data-dir을 사용해 일반 Chrome 프로필과 자동화용 세션을 분리합니다.

feat(auth): bridge saved login cookies into posting automation

After the login automation (Playwright sidecar) saves a Naver session
to a cookie file, the posting automation can now use it. When an

- add account_id to NaverDiscussionRequest / NaverPostWithCommentRequest
  / DiscussionBatchRequest (optional, defaults to None)
- add naver_automation::cookie_bridge: pure Playwright-cookie ->
  CDP Network.setCookie param conversion, unit tested
- add CdpClient::inject_account_cookies
- add optional "로그인 계정 ID" input to the batch UI
- document the bridge in ADR-0007 and the batch UI guide

End-to-end (login -> file -> inject -> post) only runs on the Windows
build; on Linux/WSL the login sidecar is a stub, so only the cookie
conversion is unit-verified here.

### ca61e3a71fe0951fdde306c1d7a5ef9c023a8310

작성자: vscodereader

fix(build): run sidecar bundler without Node TypeScript support

bundle-login is plain JavaScript with no TypeScript syntax, but the
build:sidecar script ran it via `node --experimental-strip-types`,
which fails with ERR_NO_TYPESCRIPT on Node builds that lack the
type-stripping (Amaro) support — breaking `pnpm build` and the Windows
sidecar binary build on such machines.

Rename bundle-login.ts to bundle-login.mjs and run it directly with
node. This is cross-platform, needs no TypeScript runtime support, and
keeps working on official Node / CI. No logic change.
