## PR 본문 원문

## 무엇을
종목토론방(forum)에서 댓글작성 → **특정 게시글**(url) + 글 링크를 넣으면, **종목 선택 없이** 그 링크의 글에 바로 댓글을 단다. 게시 버튼도 즉시 활성화된다.

## 왜 (기존 문제)
- 게시 모달이 forum 계정에 **종목(종목토론방) 선택을 강요**하고, 미선택 시 게시 버튼이 비활성이었다.
- forum 댓글 백엔드는 `open_random_discussion_post()`로 **무작위 글**에 댓글을 달아 의도와 다른 글에 달렸다.
- url 댓글 특례는 **카페(naver) 경로에만** 존재했고 forum엔 없었다(`urlTarget`도 카페 전용 파서라 forum URL 미해석).

## 어떻게
- `parseForumArticleUrl`: `stock.naver.com/.../discussion/{id}` → {code, postId, url}. 백엔드 packet client가 키로 쓰는 경로 형태만 허용·재정규화.
- publish-modal: forum+comment+url이면 계정당 잡 1개(URL 타겟, 종목 루프 생략). `targetsOk`/`commentReady`에서 forum 종목요구 면제, forum URL도 대상 해석으로 인정. `ForumTarget.commentUrl`에 글 URL 동결.
- IPC: `ForumTarget`/`ForumPublishRequest`/`NaverDiscussionRequest`에 `comment_url` 추가(모두 `#[serde(default)]`, **빈값=기존 동작** 하위호환).
- queue_runner: `plan_to_forum_requests`가 comment_url 대상을 per-종목 묶음과 분리해 **글 1개=요청 1건**(댓글 전용)으로 풀고, 일반 대상은 기존대로 계정별 묶음.
- naver_automation: Comment 분기가 comment_url이 있으면 그 글 URL로 navigate 후 댓글(없으면 **기존 랜덤 글 동작 유지**). 글+댓글 매크로의 검증된 빌딩블록 재사용.

## 무손상
최신글/인기글, 카페/밴드 동작은 **무변경**.

## 테스트
- TS: `parseForumArticleUrl` 5케이스, forum url-comment 게시버튼 활성·plan 동결.
- Rust: comment_url 대상 → 단일 url 요청 분리, 일반 대상 무변경.
- 전체 vitest 310 통과, tsc 통과, lint 통과, forum/discussion_batch/naver_automation Rust 테스트 통과.
