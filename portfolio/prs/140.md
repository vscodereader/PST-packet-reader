## 요약

네이버 CDP 로그인(`src-tauri/src/auth/login_flow.rs`)을 **그대로 미러링**해
**band.us 이메일 로그인**을 별도 병행 모듈 `src-tauri/src/band_auth/`로 추가했다.
로그인 "장소"만 band.us로 바뀌고, 스텔스·사람 같은 키 타이핑·ADB IP 로테이션·결과
분류(성공/비번오류/차단) 로직은 그대로 재사용한다. CDP 방식 유지(패킷 리플레이 금지,
ADR-0009).

## band.us 로그인 흐름 (패킷 분석으로 도출)

2단계: 이메일 입력 → 확인 → 비밀번호 입력 → 확인.

| 단계 | URL | 셀렉터 |
|---|---|---|
| 이메일 | `auth.band.us/email_login?keep_login=false` | `#input_email` → `#email_login_form button[type=submit]` |
| 비번 | `auth.band.us/email_login/password` | `#pw` → `#email_password_login_form button[type=submit]` |
| 성공 | `www.band.us/` | `BUC` 쿠키(.band.us) |
| 차단 | `auth.band.us/show_user_account_status` | URL 신호 |
| 비번오류 | `email_login/password` 머무름 | URL 신호 |

비밀번호는 band 페이지 JS가 클라측 암호화(rkey/akey/signature/timestamp)하므로 값만
꽂지 않고 실제 키 이벤트로 타이핑한다(네이버와 동일 이유).

## 변경 범위

**신규 (대부분)**
- `src-tauri/src/band_auth/` — login_flow / login / cookies / queue / mod / paths / util
  (순수 함수 단위테스트 35개 포함; classify·decide_loop_step·key_info·type_delay·
  BUC 쿠키검증·만료 등 네이버 테스트 미러)
- `src/features/band-accounts/` — 자족형 `BandAccountList` 컴포넌트 + 테스트(11개)

**기존 파일 변경 = additive wiring 뿐 (네이버 동작 무수정)**
- `src-tauri/src/auth/mod.rs` — ADB 회전 재사용 위한 재노출 **1줄**(가시성만 확장, 동작 무변경)
- `src-tauri/src/lib.rs` — `enqueue_band_login`·`get_band_queue_status` 커맨드 등록 + `BandQueueState` 관리

밴드 쿠키는 `cookies-band/`에 저장해 네이버 쿠키와 분리. 큐는 기존 `QueueStatus`
타입을 재사용(새 ts-rs 바인딩 없음). 비밀번호는 어떤 로그에도 남기지 않는다.
