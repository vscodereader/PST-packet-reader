## 무엇을

게시(PACKET/HTTP) 경로를 CDP 로그인 트레이스만큼 **원문 그대로** 남긴다. 지금까지는 응답 **바디**만 (`packet_client ... body={...}`) 찍혔고, 요청 라인/헤더/바디와 응답 헤더는 로그에 없었다.

## 어떻게

- `packet_client.rs` 의 **모든 나가는 요청(11개 `.send()` 지점)** 을 하나의 헬퍼 `send_traced(&client)` 로 라우팅.
  - 요청: `→ {METHOD} {url}` + 모든 요청 헤더(`name: value`) + 바디(있으면 UTF-8 lossy) 원문.
  - 응답: `← {status}` + 모든 응답 헤더 원문. (응답 **바디**는 기존 `body={...}` 로그가 이어받아 요청원문 + 응답헤더 + 응답바디 = 100% raw.)
  - CDP 트레이스와 같은 규약으로 `target: "packet"` 에 남긴다.
- **기본 ON.** 끄려면 `PSTMACRO_PACKET_TRACE=0`(또는 `false`/`off`) — `cdp_trace_enabled` 규약 그대로.
- **마스킹 최소화:** `Cookie`/`Set-Cookie` 포함 전부 원문(사용자가 raw 로 디버그). 로그인류 비밀값(`eccpw`/`pw`/`password`)만 `•`. 쿠키 원문 로깅의 유출 위험은 헬퍼 doc 주석에 명시.
- 실행 클라이언트를 인자로 받아 `self.client`(리다이렉트 추종)와 npay 가입용 `redirect::none` 클라이언트가 각자 정책으로 실행되게 함(둘을 섞으면 가입 홉 추종이 깨짐).
- 기존 `실제 API 호출` / `패킷 HTTP 응답 OK ... body={...}` 로그·재시도·에러매핑은 전부 유지, 트레이스는 **추가**.
