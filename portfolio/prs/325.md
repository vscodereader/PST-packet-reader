## 변경 요약
1. **미분류 게시 실패 → '에러' 상태 전환** (`queue_runner.rs`)
   - `apply_waiting_for_successful_posts`가 차단/대기초과/대기 3버킷만 분류해, 그 밖의 실패(약관 동의하기 비활성·버튼 못찾음, 응답읽기 IO 실패 등)는 계정이 활성으로 남던 버그. `errored_post_login_ids()` 신규 추가 + 우선순위 `차단>대기초과>에러>대기`. 테스트 2건.
2. **네이버페이 약관 자동동의 견고화** (`browser_flow.rs`)
   - 라벨 `.click()`이 React 컨트롤드 체크박스에 안 먹거나 고정 sleep으로 늦은 활성화를 놓쳐 '동의하기'가 비활성으로 남던 문제. `ensureChecked`(체크 검증+이벤트 디스패치) + `waitUntil`(최대 6초 폴링) + 실패 시 체크 상태 진단.
3. **대기초과 시 종목 게시 자동 재시도 + 게시 페이지로드 타임아웃 상향** (`discussion_batch.rs`, `naver_automation.rs`, `post_form.rs`)
   - 일시적 시간초과/HTTP500만 최대 2회 재시도(3초 간격). `POST_READY_TIMEOUT`(45초) 신규 — 게시 전용. `DEFAULT_TIMEOUT`(20초, 로그인 공유)은 무수정. 테스트 1건.
4. **now-큐 폴링 750→400ms** (`queue.tsx`)
   - 빠른 진행/실패가 폴링 사이로 사라져 '게시 중' 카드가 안 보이던 문제 완화. 실패는 기존대로 완료 로그(알림)에 기록.

남아 다음 배치에서 또 선택되는 원인.

errored_post_login_ids()를 신규 추가하고 paint 우선순위를
차단 > 대기초과 > 에러 > 대기로 확장한다(기존 3버킷 로직 무손상).
사용자 지시: 대기초과·보류·활성 기준이 아닌 실패는 전부 Error로.

fix(posts): 네이버페이 약관 자동동의 견고화 (체크 검증·조건 폴링)

- ensureChecked(): 라벨 클릭 후 input.checked를 검증하고, 안 되면 input 직접
  클릭 + input/change 이벤트 디스패치로 React 상태까지 반영.
- waitUntil(): 고정 sleep 대신 최대 6초 폴링하며 매 회 미체크 필수항목 재시도.
- 실패 시 필수항목 체크 상태(on/off/none)를 에러 메시지에 남겨 진단 가능.
