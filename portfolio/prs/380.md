## 1. Chrome 완전 종료(프로세스 트리) + '게시 완료' 신호 + 잔존 크롬 표시
`ChromeHandle::drop`이 `child.kill()`만 호출해 Windows에서 메인 chrome.exe만 죽고
렌더러/GPU/crashpad 등 자식 헬퍼가 고아로 남아 작업관리자에 누적됐습니다(15계정 ×
병렬 종토 게시). 임시 프로필도 잠겨 삭제 실패했고, 이 고아 누적이 캡차(봇탐지 점수)의
유력 원인으로 지목됐습니다.

- Windows: `taskkill /PID <pid> /T /F`로 프로세스 트리(자식 포함) 통째 종료 후
  `wait()`로 메인 회수. `CREATE_NO_WINDOW`로 콘솔 깜빡임 없음. 비-Windows는 기존
  `kill()`+`wait()` 유지.
- 종토 게시(queue_runner): `run_forum_publish` 반환 후 `drop(chrome)` **전에** 종목별
  실제 결과를 원문 그대로 남기고 "게시 완벽 완료 확인" 마커를 찍어, kill이 게시 도중이
  아니라 완전 완료 후에만 일어남을 로그만으로 증명할 수 있게 했습니다.
- 잔존 pstmacro 크롬 개수를 best-effort로 세어 로그(N>0이면 warn) + `running_chrome_count`
  커맨드로 노출. 계정관리 헤더에 "실행 중 크롬 N개" 지표(2초 폴링)를 추가해 작업관리자
  없이 확인합니다.

`account_cookie_expiry(id)` 커맨드가 로그인 유지 쿠키(NID_SES/NID_JST/NID_SAUTO/NID_AUT)의
만료 시각 최댓값을 반환하고, 전부 세션 쿠키면 None. 태그 필터·검색은 유지됩니다.

로그인은 현재 IP로 진행하도록 했습니다(사수 지시). `bootstrap_runtime`은 ADB를
요구하지 않아 별도 폴백이 필요 없었습니다.
