### d931a144b286fc5afb0b0499f4fdc38384396883

작성자: vscodereader

fix(auth): make CDP login survive captcha, 2FA, and device registration

Verified end-to-end against a real Naver account; fixes three defects that
each aborted login before completion (none were visible without a live run):

- Misclassified credentials: the bad-credential probe matched the always-
  present (hidden) "Caps Lock is on." element, so every attempt returned
  "wrong password" on the first poll. Require the error element to be
  actually visible (offsetParent) with non-empty text; apply the same
  visibility guard to captcha/otp probes (new `visible_exists`).
- Captcha/challenge gave up instantly: a challenge returned ChallengeRequired
  immediately even in the headed window. login_flow::run now takes
  `wait_for_human` — headed waits for the user to solve the captcha/2FA until
  success or timeout (per the design's "show window, time out" requirement);
  headless still returns at once so the orchestrator promotes to headed.
  Split LOGIN_TIMEOUT into HEADLESS_TIMEOUT (40s) / HEADED_TIMEOUT (180s).
- Post-login device page read as "blocked": the "새 기기 등록" interstitial
  (on nid.naver.com, no login form, cookies not yet set) tripped the blocked
  heuristic. Reuse browser_flow's `click_device_dontsave_if_present` (now
  pub(crate)) each poll to dismiss it, and in headed mode keep waiting through
  transient blocked states instead of failing. Surface the last URL on timeout.
