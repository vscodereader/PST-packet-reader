## 배포 후 버그 (실기기 하위 COM, 2026-07-16)
자동(선택)로그인이 "로그인 폼 로딩 대기 중"에서 무한 대기 → 창 닫으면 "폼(#id/#pw)을 찾지 못했습니다" 실패. 타이핑 자체가 시작 안 됨, 쿠키 미생성, 로딩바 무한, 뒤 계정 큐 적재.

## 원인 (패킷 3종 + 로그 정독)
네이버가 로그인 폼을 v3→v4로 재작성. 로그인 버튼 `input[type=submit]#log.login` → `button[type=button]#loginBtn_column/row`(반응형). 앱 `wait_for_login_form` 게이트의 form_ready(버튼 존재 조건)가 영원히 false → DOM 완전 로딩 게이트가 안 열림.

## 내부 불변 (확정)
dynamicEcKey(ECC)·eccpw/dynamicKey/bvsd/sessionKey·POST nidlogin.login·login.js ECC 암호화 전부 그대로. **UI(v3→v4)만 변경 → 셀렉터만 맞춤.**

## 변경
- form_ready 버튼: `#loginBtn_column`·`#loginBtn_row` 추가(기존 유지)
- click_login_button: 신 폼 버튼, 로그인 전용 id·보이는 것 우선(패스키 오클릭 방지)
- ANTIBOT_READY_JS: default_ecc 의존 제거 → `pages/login.js` 추가
- 캡차 감지: v4 rcaptcha `#rcapt`·`#chptcha` 추가
- DOM 완전 로딩 게이트/3초 wtmncapt 대기 등 내부 무손대
