# Summary

## 1. 종목토론방 큐 실행 시 "2차 로그인" 제거

선택 로그인(1차)으로 ID/PW 로그인 → 쿠키 저장(`cookies/{loginId}.json`) → 글 작성 → 게시 → 큐 실행 시, 종토방은 `prepare_group_login`이 **또 로그인**(`process_account`)을 했다. 이 2차 로그인은 같은 쿠키 파일을 덮어쓸 뿐 불필요하다.

- **forum 게시는 매번 그 쿠키 파일을 디스크에서 새로 읽는다**(`auth/accounts.rs:83` `fs::read_to_string`) — in-memory 핸들이 아니라 **파일 경로**. 그래서 2차 로그인을 빼도 1차 로그인 때 저장된 쿠키를 그대로 사용한다(쿠키 유실 없음).
- 새 순수 헬퍼 `forum_only_group(plan, group)` — 카페(`plan.naver`) 대상이 없고 forum만인 Naver 그룹이면 `true`. 그런 그룹은 큐 실행 시 재로그인을 건너뛰고 저장 쿠키로 게시한다.
- **카페가 한 대상이라도 섞인 그룹은 그대로 회전+로그인+IP검증 유지** — 네이버 카페 10004(IP check failure) 방지. 밴드 그룹도 그대로(별도 쿠키).

## 2. 게시 진행률 분모 버그 수정

`estimate_total`이 `plan.login`이 있으면 게시 타깃이 있어도 분모를 **로그인 계정 수**로 잡았다. 그래서 3계정×3글이 `0/9`가 아니라 `0/3`으로 시작하고, 완료 수가 분모를 넘어 `5/3`·`6/3`처럼 보였다.

- 이제 **로그인 전용 아이템(게시 타깃 없음)만** 분모 = 계정 수. 게시 타깃이 동봉되면(종토방 선택 로그인 등) 분모 = **실제 게시 작업 수**.
