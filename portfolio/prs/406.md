## PR 본문 원문

## 목적
캡차 판정 근거 규명 — 봇탐지 엔진(ncaptcha wasm)에 들어가는 **재료**를 암호화 전에 캡처. `/v2/tokens` ciphertext 는 wasm 내부 랜덤키 암호화(서버 봉인)라 **복호화 불가**(pcap·엔진 추출로 확인), 그래서 평문 재료를 로그인 크롬에서 직접 관측한다.

## 동작 (기본 OFF)
- `PSTMACRO_FP_TRACE` 를 truthy(예: `1`)로 켤 때만. 미설정/`0`/`false`/`off`/`no` 는 OFF → 평소 로그인 **바이트단위 무영향**.
- 켜면 제출 직전 스냅샷을 로그에 남긴다: `[LOGIN][FP] 제출직전 재료(독립 read·엔진 payload 아님) account=xxx**** {...}`
- 재료: canvas 해시(우리 offscreen)·webgl 벤더/렌더러·audio rate·navigator(hw/screen/tz/langs/plugins/highEntropy) + **행동 카운트**(keydown/keyup/mouse*/scroll + keydown 타임스탬프).

## 탐지 안 되게 (핵심 설계)
엔진 역탐지(`_setFunctionErrorKey`=native-code 검사, `_detectFixedCanvas/Webgl`, `_setPrototype`)를 피하려 **함수/프로토타입 override 0**:
- 행동: capture 단계 **리스너 추가만**(preventDefault 안 함, mousemove/scroll passive).
- 정적: 엔진 호출 가로채지 않고 **우리가 따로 읽기만**(기존 `AUTOMATION_FINGERPRINT_JS` 와 동일 방식).
- ciphertext 크기: `fetch`/`Network.enable`(탐지표면↑) 안 씀 → pcap(SSLKEYLOGFILE) 시각·계정으로 사후 대조.
- 단위테스트 `fp_trace_js_is_additive_only_no_overrides` 가 JS 에 override 패턴 부재를 강제.

## 로그 정직성 (거짓 방지)
- 측정 실패 → `WARN`(성공으로 위장 안 함). JS 부분오류 → `WARN`(값 신뢰 금지).
- 리코더 미장착 → `behavior.installed:false` + 수치 `-1` (진짜 0 과 구분).
- 스냅샷은 읽기만 → 행동 카운트 오염 없음.

## 무손상
- 게시/밴드/카페 무관(로그인 경로 한정). OFF 기본이라 기존 흐름 무변경.
- Rust 단일 파일(login_flow.rs). auth 137 테스트 통과(신규 2 포함), 빌드 클린.

Closes #405
