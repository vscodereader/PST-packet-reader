# Summary

계정 관리 화면 '계정 추가' 옆에 **'IP 변경'** 버튼을 추가한다. 누르면 **연결된 ADB 디바이스(폰)의 비행기모드만 껐다 켜 IP를 회전**시킨다 — 로그인·게시 등 다른 동작 없음.

## 왜 필요했나

지금은 IP를 바꾸려면 **ID/PW로 로그인을 해야만** (로그인 경로에서 `toggle_airplane_mode`가 돌아) IP가 회전한다. "로그인 없이 그냥 IP만 바꾸고 싶은" 순간엔 방법이 없었다.

## 어떻게 (기존 동작 무손상 · 완전 독립 경로)

- 백엔드 `rotate_ip` 커맨드가 **로그인 경로(`auth/mod.rs:74`)와 동일하게** `assert_adb_device` → `toggle_airplane_mode` 순서로 **기존 함수를 그대로 재사용**한다. 비행기모드 ON/OFF·IP 회전 결과 로그도 기존과 동일:
  ```
  [ADB] ✈ 비행기모드 ON
  [ADB] ✈ 비행기모드 OFF — 인터넷 복구 대기
  [ADB] ─────────── IP 회전 결과 ───────────
  [ADB]   기존 IP: ... / 바뀐 IP: ... / ✓ IP 변경됨!
  ```
- **버튼과 로그인은 서로 독립**이다. 버튼은 로그인을 트리거하지 않고(ID/PW·쿠키·Chrome·게시 전혀 안 부름), 로그인도 버튼/`rotate_ip`를 거치지 않는다. 공유하는 건 **최하위 `toggle_airplane_mode` 함수 하나**(읽기 재사용)뿐.
- **기존 코드/기능은 한 줄도 변경 없음 — 순수 추가(additive).**

## Changes

- `src-tauri/src/lib.rs`: `rotate_ip` 커맨드 추가 + `generate_handler!` 등록.
- `src/shared/ipc/index.ts`: `ipc.auth.rotateIp()` 바인딩.
- `src/features/accounts/accounts.tsx`: '계정 추가' 옆 'IP 변경' 버튼(로딩 상태 + 성공/실패 토스트, 실패 시 activity 기록).

## Test

- `vitest run accounts.test.tsx` → **35 passed**(IP 변경 버튼 성공/실패 토스트 2건 신규 포함). eslint·prettier clean.
- e2e(실기기)는 작성자 직접: 폰 연결 후 버튼 → 로그인 없이 IP 바뀌고 로그에 `✓ IP 변경됨!` 뜨는지.
