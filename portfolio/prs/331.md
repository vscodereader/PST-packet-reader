## 문제
게시 흐름의 첫 HTTP 호출인 `read_login_profile`(getProfile)이 **전송 계층에서 실패**(`error sending request for url`)하면, `forum_failure_reason`이 상태코드 없는 그 메시지를 "패킷" 단어 때문에 **잠금 폴백**으로 흘려 _"게시에 실패했습니다. 계정 로그인·잠금 상태를 확인한 뒤 다시 시도해 주세요"_ 라는 **틀린 안내**가 떴다.

실제로는 잠긴 게 아니라 **망이 잠깐 끊긴 것**(특히 IP 교체 직후)이라 그 안내로는 풀리지 않는다 — #330과 같은 부류의 오안내. 백트레이스로 원인 확인(`packet_client.rs:155 read_login_profile`).

## 수정 (TDD)
- **(A) 분류 교정** — `forum_failure_reason`에 `is_network_transport_failure` 분기 추가 → 전송 계층 실패는 **"잠시 인터넷 연결이 끊겨 게시에 실패했습니다. 잠시 후 다시 시도해 주세요"**. HTTP 상태가 있으면 기존 `status_reason` 매핑이 여전히 우선(잠금·친절문 폴백 모두 보존).
- **(B) 전송 재시도** — `get_with_transport_retry`(짧은 백오프 0.5→1→2초·상한 3초·4회)를 추가해 `read_login_profile`에 적용. 연결/타임아웃/요청 오류만 재시도(디코드/본문/리다이렉트 제외). POST 429용 70초 백오프(`post_with_retry`)와는 분리.
- **(C) 원인 확정** — 마지막 실패 메시지를 기존 `util::describe_reqwest_error`로 만들어 **source 체인**(연결 거부/타임아웃/DNS)까지 노출. 다음부턴 "대기초과였는지 연결 끊김이었는지" 로그로 확정 가능.

기존 `util::reqwest_kind`를 `pub`로 열어 재사용(신규 분류기 미생성). 기존 흐름·메시지·테스트 불변.
