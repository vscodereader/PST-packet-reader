## 배경 — 정상 vs 캡차 패킷 1:1 대조 (wireshark 풀패킷, keylog 복호화)

**캡차 직전까지 인증경로가 사실상 전부 동일했습니다:**
- 요청 순서/경로/메서드/상태코드 동일

- 보낸 쿠키 이름·개수 동일(NID_JST, NNB, SRT30/5, NAC, NACT, nid_slevel, BUC), Set-Cookie 동일
- 요청 헤더 **값**도 동일(user-agent, 모든 `sec-ch-ua*`, device-memory, dpr, viewport-width, accept-language …)
- 차이는 **세션 랜덤값**(dynamicKey/eccpw/wtoken/tokenId), content-length 몇 바이트, `rtt`(50/100), 광고 픽셀뿐 — 인과 아님

**갈림은 딱 하나** — `POST nidlogin.login` **응답**: 성공=`NID_AUT/NID_SES` 발급→finalize, 캡차=rcaptcha(receipt) 페이지. 20판도 `/v2/tokens` 200 + 정상 tokenId 발급(엔진 실패 아님). `cipherText`(지문 채점 결과)는 암호화라 내용은 못 봅니다.

## 가설
`봇점수 = baseline(상수) + accumulator(변수) > 임계 → 캡차`
- **baseline**(매판 동일): CDP 구동, **override(JS게터 tell)**, 고정 하드웨어 지문
- **accumulator**(변수): 같은 (IP+지문)으로 최근 창에 몇 판 했나
- 16성공→3차단→3캡차의 시간순 단조 악화 = accumulator가 판별자. baseline은 상수라 판별자는 아니지만 "임계까지 여유"를 깎습니다.

**이 브랜치(B)는 baseline을 공격합니다.** (A 브랜치는 accumulator)

## 제거하는 override의 정체
`src-tauri/src/auth/login_flow.rs` `STEALTH_INIT_JS`:
```js
Object.defineProperty(Navigator.prototype,'webdriver',{get:()=>false,...});
Object.defineProperty(Navigator.prototype,'languages',{get:()=>['ko-KR','ko','en-US','en'],...});
```

## 이 override는 왜 만들었나 (git 기록)
- **`0bda79e` (2026-06-04, #100)**: "ncaptcha는 점수형이라 자동화 지문도 본다. CDP로 띄운 Chrome은 `navigator.webdriver`를 노출 → 캡차. navigate 전에 마스킹" + `--disable-blink-features=AutomationControlled`.
- **`60d149a` (2026-06-29)**: "지문 A/B 실측: 손 로그인=성공/매크로=캡차인데 **딱 두 필드만 달랐다 — webdriverOwn(false/true), languages(4개/1개)**. 인스턴스 defineProperty가 own=true 흔적을 남겨서 → `Navigator.prototype`으로 옮겨 own=false 정렬 + languages 4개로 맞춤."

즉 override는 그때 측정된 실제 지문 차이 2개를 없애려던 **정당한 수정**이었습니다.

## 왜 이제 다시 제거하나
1. **중복이 됐다**: `#393`(chrome.rs `--accept-lang=ko-KR,ko,en-US,en`)로 **native `navigator.languages`가 이미 4개**, `--disable-blink-features`로 **native `navigator.webdriver`가 이미 false**. override의 '값 맞추기'를 이제 크롬 플래그가 네이티브로 달성.
2. **오히려 tell을 남긴다**: override는 값은 맞지만 **JS 게터**라 `getOwnPropertyDescriptor(...).get.toString()`이 `()=>false`로 나온다(네이티브는 `[native code]`). WASM의 `_setFunctionErrorKey`/`_setPrototype`는 이 게터 네이티브성까지 본다. **06-29 A/B는 webdriverOwn(bool)·languages(개수)만 봤고 게터 네이티브성은 확인하지 못했다** → 이 tell이 그대로 남아 있었습니다.

→ override 제거 = 네이티브 게터로 복귀해 **게터 변조 tell 제거**(값은 크롬 플래그가 유지).

## 변경 내용
- `STEALTH_INIT_JS`를 no-op(`(()=>{})();`)으로 — defineProperty 2줄 삭제.
- `cargo check` 통과.

## 빌드 후 검증 (중요)

- `languages`가 **1개로 회귀** → `--accept-lang`이 native를 못 채운 것 → 되돌리고 다른 방법 필요.
