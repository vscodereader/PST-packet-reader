## PR 본문 원문

"진단만 남기지 말고 통제 가능한 건 실제로 되게" 라는 요구에 따라, 게시가 안 되던 3가지를 **실제 동작하도록** 고쳤다. 로그인 경로/설계서/Admin UI는 무수정.

## ① 쿠키 못찾음 (로그인 성공인데 게시 때 NID 쿠키 없음)
- **도메인 정규화**: host-only `nid.naver.com` 쿠키를 `.naver.com` 와일드카드로 보정해 `stock.naver.com`에도 전송(`normalize_naver_domain`).
- **수집 누락 보완**: getCookies URL에 `https://nid.naver.com` 추가(`static.nid`≠`nid`).
- **세션 만료 구분**: 게시 직전 navigate가 로그인 페이지로 가면 "세션 만료=재로그인"으로 명확히 차단(엉뚱한 "쿠키 못찾음" 대신). URL은 로그에만.

## ② 디스크 IO 실패 (`io: …`)
- **복원**: 디렉터리 보장 + 원자적 쓰기(임시파일→rename) + 백신/인덱서의 일시적 잠금(Windows 공유위반 os error 32·권한거부)에만 백오프 재시도.
- **진단**: 경로+동작+OS 코드를 메시지에 담아 외부오류(500/403)와 "로컬 디스크 오류" 구분.

## ③ 동의하기 비활성/못찾음
- **DOM 무관 전수 스캔**: 하드코딩 id/절대 xpath 제거, 컨테이너 내 모든 체크박스를 라벨 유무와 무관하게 checked 보장(`if(!label)continue` 결함 제거).
- **버튼 다중 단서**(텍스트+submit+폼 최하단) + **실패 시 DOM 스냅샷** 진단.

fix(posts): 쿠키 못찾음 — 도메인 와일드카드 정규화 + nid.naver.com 수집 + 세션만료 구분

로그인 성공(활성) 계정인데 게시 때 'Chrome에서 네이버 로그인 쿠키 못찾음'이
나는 문제. 원인 2가지를 코드로 차단한다(통제 가능 영역).

- 도메인 스코프 불일치: NID_AUT/NID_SES가 host-only(nid.naver.com)로 저장되면
  stock.naver.com엔 전송 안 됨. cookie_bridge에서 naver.com 계열 host-only를
  .naver.com 와일드카드로 정규화해 주입(normalize_naver_domain + 테스트).
- 수집 누락: build_naver_packet_client의 getCookies URL에 nid.naver.com 추가
  (static.nid ≠ nid).
- 세션 만료 구분: 게시 직전 navigate가 nid.naver.com(로그인 페이지)로 가면
  '세션 만료=재로그인'으로 명확히 차단 처리(엉뚱한 '쿠키 못찾음' 대신). URL은
  로그에만(토큰 노출 방지).

느린 폰 데이터는 로그인↔게시 간격을 늘려 세션 만료를 가속하는 외부 요인이고,
위 정규화/세션구분은 그 영향을 코드로 흡수한다.
