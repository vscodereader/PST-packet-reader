## PR 본문 원문

두 가지를 함께 처리.

## 1. 로그인 — '돔이 전부 제대로 붙음'을 엄격 판정 (사수 의도)
기존엔 "그 순간 DOM의 iframe만 complete"로 판정 → 늦게 주입되는 봇탐지/암호화 스크립트가
안 붙은 채 타이핑 → 캡차. iframe 개수는 캡차의 진짜 원인이 아님.

세 신호를 **모두** 만족할 때만(폴백 없음) 진행:
- ① form_ready: 상위문서 complete + #id/#pw 보임·입력가능 + 로그인 버튼
- ② resources_settled: 직전 폴 대비 완료 리소스 수 불변 = 새로 끝난 로딩 없음 = 페이지가 받는
  **모든 리소스(문서·스크립트·iframe·늦게 주입되는 것 포함)** 로딩 정착 ← "그 순간 iframe만" 한계 제거
- ③ antibot_ready: wtm.pstatic.net/default_ecc/ncaptcha 등 봇탐지·keydown 암호화 스크립트가
  performance resource timing에 실제 로드로 잡힘

셋 다 + 연속 3회(FORM_READY_STABLE_POLLS, 유지) 안정일 때만 타이핑. 10초 안에 다 안 붙으면
타이핑하지 않고 로그인 실패(캡차 유발 방지 우선).

## 2. 게시큐 — 돌아가는 작업만 표시, 결과는 알림에서
완료/실패/도중 차단 아이템을 큐에 Done 카드로 남기던 것 제거. finish_item을 apply_cancel_now로
되돌려 끝난 아이템은 큐에서 제거. 결과는 실행 중 알림 로그·계정 상태에 이미 기록됨. running
아이템은 그대로 보여 가시성 유지.

## 테스트
- login_form_gate_open(폼+리소스정착+안티봇 모두) 단위 테스트, login_flow 46건 통과.
