# Summary

윈도우에서 `pnpm tauri build`가 다음 에러로 실패하던 문제를 고친다:
```
resource path `target\x86_64-pc-windows-msvc\release\pstmacro.pdb` doesn't exist
```

`tauri.windows.conf.json`이 디버그 심볼(`pstmacro.pdb`)을 번들 리소스로 포함하는데(#199 — release backtrace 심볼화), 이 `.pdb`는 **링커가 빌드 스크립트 이후에** 만든다. fresh 윈도우 빌드에서는 `tauri_build`의 리소스 존재 검사가 "파일 없음"으로 먼저 실패한다(닭-달걀). 동기가 리눅스에서 빌드할 땐 이 윈도우 전용 설정이 적용되지 않아 안 걸렸고, 윈도우 fresh 빌드에서만 터졌다.

## Fix

`build.rs`에서 `tauri_build::build()` 호출 **전에** 빈 자리표시 `.pdb`를 만들어 둔다. 리소스 존재 검사를 통과하고, 실제 `.pdb`가 링크 시점에 그 자리를 덮어쓴다(자리표시는 흔적 없이 대체, 백트레이스 기능 유지). 윈도우 전용 `#[cfg(target_os = "windows")]`이라 리눅스/맥 빌드엔 영향 없음.

## Test

- `cargo build --lib` 통과(리눅스에선 cfg 블록 제외, 문법 유효성 확인). fmt clean.
- 윈도우 fresh `pnpm tauri build`가 .pdb 에러 없이 진행됨(작성자 환경 확인 예정).
