## PR 본문 원문

tshark 패킷(계정 잠금) 직접 분석으로 확인한 실제 버그.

## 발견
잠금 계정 로그인 = `nidlogin.login` → **HTTP 200** + 본문:
> "비정상적인 활동이 감지되어 아이디를 **보호(잠금) 조치중**입니다 … '본인 확인하기'를 통해 해제할 수 있습니다."

에러 코드 없음·성공 쿠키(NID_AUT/NID_SES) 없음. 그런데 기존 감지는 `'아이디 잠금조치'` 문자열만 봐서 **이 현행 페이지를 못 잡고** 일반 `Blocked`로 떨어져 *"잠시 후 다시 시도"* 라는 **틀린 안내**가 떴다(잠긴 계정은 재시도로 안 풀림).

## 수정
- `locked` 감지를 `'아이디 잠금조치'`(기존 보존) + `'보호(잠금)'` + `'비정상적인 활동이 감지'` 중 하나로 확장. 오탐 방지 위해 잠금 페이지 고유 문구만 사용.
- → `Locked`로 분류돼 `outcome.rs`의 정확한 안내("네이버 본인 확인으로 잠금 해제")가 표시됨. 메시지 매핑은 이미 정확했음.

## "HTTP 코드를 넣어달라"에 대해
네이버는 잠금에도 **200**을 줍니다(에러 코드 없음). 그래서 추출할 HTTP 코드가 없고, **본문 식별이 유일한 신호**입니다. 코드 대신 검출을 고쳐 올바른 분류·안내가 뜨게 했습니다.
