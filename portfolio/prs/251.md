# Summary

'IP 변경'(#247) 후속. IP가 그대로 유지되던 문제를 비행기모드 토글 신뢰성으로 보강하고, 변경 결과(원래/바뀐 IP)를 **토스트·게시 큐 밑 알림**에 표시한다. 사수 피드백 반영.

## 왜 필요했나

- **IP가 안 바뀌는 경우** — 사수: 비행기모드가 너무 빨리 켜졌다 꺼져 단말 라디오가 실제로 순환할 새가 없음. 토글이 정말 먹혔는지 확인할 길도 없었다.
- **결과가 안 보임** — IP 변경 여부가 로그(`pstmacro.log`)에만 남고, 토스트엔 "변경했어요", 알림엔 아무것도 안 떠 실제로 바뀌었는지 알 수 없었다.

## 어떻게 (토글 로직 외 무손상)

1. **상태 확인 로그 추가** — 비행기모드 ON/OFF 직후 `settings get global airplane_mode_on`으로 실제 상태를 읽어 한 줄(`└ 상태 확인: 비행기모드 ON(켜짐)/OFF(꺼짐)`) 더 남긴다. 조회 실패는 토글을 막지 않고 표기만.
2. **대기 3초** — 켠 뒤 끄기까지 대기를 1초 → 3초(`ADB_AIRPLANE_ENABLE_SECS`).
3. **결과를 UI로** — `rotate_ip`가 `IpRotation { before, after, changed }`를 반환. `toggle_airplane_mode`가 **이미 계산하던** before/after를 그대로 surface(로그인 호출부는 값을 버려 **동작 무변경**). 버튼은 변경 시 초록 토스트 `IP 변경됨 — 원래: X / 바뀐 IP: Y` + 알림(success), 그대로면 주황 토스트 + 알림(info).

> 로그인/밴드의 IP 회전 동작은 그대로다(`toggle_airplane_mode().await?;`가 반환값을 버림). 토글 로직 외 다른 코드 변경 없음.

## Changes

- `auth/config.rs`: `ADB_AIRPLANE_ENABLE_SECS` 1 → 3.
- `auth/adb.rs`: `airplane_mode_state()` 상태 조회 + `airplane_state_label()` 순수 파서(+테스트), 토글에 상태 로그 2줄, `IpRotation` 반환.
- `auth/mod.rs`: `IpRotation` 재노출.
- `lib.rs`: `rotate_ip` → `IpRotation` 반환.
- `ipc/index.ts` / `accounts.tsx`: 토스트·알림 표시(+테스트).
