## 배경
IP 변경 버튼이 비행기모드 토글 후 **고정 3초**(`EnsureIpChange`)만 기다리고 IP를 1회 읽었다. 로그인 경로에는 이미 더 정확한 방식(`WaitForIpChange`)이 있었다 — ON → `ping 8.8.8.8` fail로 폰 인터넷 끊김 확인 → OFF → 외부 IP가 **실제로 바뀔 때까지 폴링** → 즉시 종료.

## 변경
- `rotate_ip`(IP 변경 버튼)을 로그인과 동일한 방식으로 통일. 버튼은 `toggle_airplane_mode`만 호출하므로 **IP 변경 확인 시점에 정확히 끝남**(연결 안정화로 넘어가지 않음 — 요구사항).
- 모드가 하나만 남아 `IpRotationMode` enum + `mode` 파라미터 제거, `toggle_airplane_mode`를 단일 동작으로 단순화.
- 죽은 코드 정리: `ADB_AIRPLANE_ENABLE_SECS`(3초 상수), `airplane_mode_state`/`airplane_state_label`(EnsureIpChange 로깅 전용) + 해당 테스트, 호출부 인자 제거.

## 트레이드오프
- 고정 3초 대신 실제 변경까지 대기라, IP가 안 바뀌는 환경(CGNAT/WiFi 유지)에선 상한 `ADB_INTERNET_TIMEOUT_SECS=30초`까지 기다렸다 `changed=false`로 끝남. 정상일 땐 보통 수 초 내 종료.
