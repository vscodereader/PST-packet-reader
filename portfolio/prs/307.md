## Summary

- 기존 게이트의 ③`antibot_ready`는 봇탐지/암호화 스크립트가 **파일 다운로드**됐는지만 봐서, keydown 암호화 후킹이 **실제로 입력칸에 붙기 전** 타이핑→봇탐지/캡차가 날 수 있었다(사수 의도 "DOM 다 로드 후 입력" 미충족 지점).
- `CdpClient::expr_has_listener`: `DOMDebugger.getEventListeners`로 `#pw`/`#id`에 **keydown 리스너가 실제 붙었는지 직접 관측**(네이버 내부 전역명 추측 없이). 어떤 CDP 단계든 실패하면 false.
- `wait_for_login_form` 조건 ④: DOM(①②③) 준비 동안 후킹 설치를 관측해, 확인되면 통과.
- **안전 폴백(무한 대기 방지)**: 관측이 안 되거나 네이버가 구조를 바꿔도 DOM 준비가 `HOOK_CONFIRM_MAX_POLLS`(~5초) 지속되면 **미확인 경고 로그 후 진행** — 게이트엔 타임아웃이 없어 하드 조건이 영원히 false면 로그인이 멈추므로, 그걸 막는다.
- 확인 시 INFO에 "keydown 암호화 후킹 설치 확인", 미확인 진행 시 WARN(자세히 보기 진단의 "안티봇 미설치"와 연결).
