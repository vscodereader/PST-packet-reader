# Summary

실행 **중인** 카페/밴드 작업을 **계정 그룹 경계(안전지점)에서 중지**하고, 더 높은 우선순위
작업(로그인 1순위·종목토론방 2순위)을 먼저 실행한 뒤 **남은 그룹만 재개**한다. 사수 지침 2차.

- **삭제가 아니라 중지.** 양보 시 아이템을 큐에서 빼지 않고 **잔여 plan(아직 안 한 그룹만)으로
  Waiting 복귀**(`apply_yield_now`). 완료 그룹은 plan에서 빠져 **재개 시 중복게시 0.**
- **안전지점 = 계정 게시 그룹 경계.** 각 그룹(`[회전→로그인→IP검증→게시]`)이 #10004 때문에
  원자적이라 그 사이가 "여기까지 하고 멈춰도 무방"한 지점이다. 그룹은 시작 직전에만 양보 →
  부분 그룹 상태가 없어 잔여 plan 복원이 자명·안전.
- **즉시 전환.** 양보 후 sleep 없이 다음 루프에서 선점 아이템을 바로 집어 실행("칼같이").
- **누락 0.** 양보 시 이미 끝난 그룹은 완료 로그(LogBatch)로 flush.

게시 엔진·로그인·카페/밴드/종토 실행 로직·취소(`apply_cancel_now`)는 **불변(additive)**.

## Priority preemption rule

`should_yield_now` — 실행 중 아이템보다 **우선순위가 엄격히 높은(값이 작은) Waiting**이 있으면 양보:

| 실행 중 | 대기 | 동작 |
| --- | --- | --- |
| 카페/밴드(2) | 종토방(1) | 중지 → 종토 먼저 → 재개 |
| 카페/밴드(2) | 로그인(0) | 중지 → 로그인 먼저 → 재개 |
| 종토방(1) | 로그인(0) | 중지 → 로그인 먼저 → 재개 |
| 종토방(1) | 종토방(1) | **계속 진행**(동순위, 선점 안 함) |
| 카페(2) | 카페(2) | **계속 진행**(FIFO 유지) |
